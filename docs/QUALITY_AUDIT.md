# 미니 미드가르 — 사건 전달 점검 (퀄리티 가이드 적용)

2026-10-07 · 기준 코드: 커밋 `bca5169` (main) · 기준 문서: `RiftLoopPrototype/docs/퀄리티 가이드.md` v1.0, 적용 예시 `growth-tension-v6.md`

이 문서는 **분석만** 했다. `src/`, `tools/`는 고치지 않았다.

- **방법:** 코드를 읽고 타이밍을 계산했다. 사건 빈도는 헤드리스 프로브로 셌다. 프로브는 스크래치패드에서 `World`를 `fx=true`로 시뮬 5분 돌렸다(시드 3). 파티는 `applyExp`로 레벨만 맞춘 임의 빌드라 실제 플레이어 빌드와 다르다.
- **시간 규칙(모든 타이밍의 바탕):**
  - 월드는 50ms 고정 스텝으로 돈다(`world.ts:121`, `245-251`).
  - `after(ms)` 예약은 그 시각 이후 첫 스텝에서 실행된다(`world.ts:263-270`). 그래서 140ms 예약은 **150ms**에, 220ms 예약은 250ms에 실행된다.
  - 공격·피격·사망 포즈의 시간 `t`도 월드 시간이다(`field.ts:847`, `871-874`). 그래서 이 동작들은 **20fps**로 그려진다. 반면 이동·대기·시전 포즈와 이펙트·숫자·투사체는 렌더러 시계(60fps)를 쓴다.
- **한계:** 브라우저 실행 화면으로는 확인하지 않았다. 가이드 2장 3항대로 P1 항목은 고치기 전에 실제 1배속 화면에서 재현해야 한다. 렌더 파일(`field.ts`·`hero.ts`·`monster.ts`)은 다른 세션이 아트 작업으로 바꾸는 중이다. 줄 번호는 `bca5169` 기준이다.

> 자동 사냥 중인 파티가 **지금 누구를 치고 누구에게 맞고 있는지(위험)**, 그리고 **무엇을 얻었고 무엇이 달라졌는지(레벨·포인트·드롭·카드)**를 화면만 보고 알 수 있어야 한다. 그 결과로 다음 할 일(스탯·스킬 분배, 전직, 장비 교체, 카드 꽂기, 포션, 사냥터 이동, 보스 소환)을 고를 수 있어야 한다.

## 3. Top 5 문제와 구현 스케치

가이드의 원칙은 **실제 값·저장은 즉시, 표시는 접촉 시점**이다. 이 게임은 월드가 이미 `after()`로 판정을 늦게 실행한다. `after()` 타이머는 저장되지 않으므로 중복 지급 위험이 없다. 따라서 근접 공격은 **판정 시각은 그대로 두고 포즈를 판정에 맞추는 쪽**(렌더만 수정, 밸런스 무변경)이 가장 싸다. 투사체는 월드 쪽 발사 시각만 옮긴다.

### Top 1. 아군 공격의 '접촉'이 동작보다 먼저 온다 (근접 평타·근접 스킬·활) + 공격 포즈 20fps

가장 자주 나오는 사건이다(사막 150회/분 휘두름, 설원 90회/분 화살). 대표 타임라인은 아래와 같다. 기사는 delay 692ms라 포즈가 420ms, 잠금이 320ms다.

| 시각 | 월드 | 화면 |
|---|---|---|
| 0 | `attack`, `swing` 소리, `after(140)` | 팔을 뒤로 젖히기 시작 |
| 50·100 | — | 준비 자세 (20fps라 2프레임) |
| **150** | 판정, HP 감소, 숫자·스파크·타격음 | **무기가 머리 뒤 205°** |
| 200 | — | 무기 123° (내려오는 중) |
| ≈218 | — | 칼날이 정면 90°를 지남 — **그려지는 프레임 없음** |
| 250 | — | 이미 지나 77° |
| 350 | 잠금 해제 → `ready` | a 0.71에서 대기 자세로 튐 |

활(헌터 delay 617, 거리 ≈125px): 0ms에 화살이 출발한다 → 167ms에 화살이 꽂히고 사라진다 → 250ms에 숫자가 뜬다 → **≈252ms에 시위를 놓는 자세**가 나온다.

구현 스케치:

1. **렌더 보간 시간을 쓴다.** `World`에 `get renderTime() { return this.time + this.acc; }`를 둔다(`acc`는 지금 private, `world.ts:150`). `field.ts`의 `w.time - h.stateT`(`847`), `w.time - h.hurtAt`(`849`), `w.time - m.stateT/hurtAt/deadAt`(`871-874`), 스폰 계산을 `w.renderTime` 기준으로 바꾼다. 공격·피격·사망·스폰 동작이 60fps가 된다.
2. **타이밍 상수를 한 곳에 둔다.** 새 `src/game/timing.ts`에 아래를 둔다.
   ```ts
   export const MELEE_CONTACT = 140; // world normalAttack after()
   export const SKILL_CONTACT = 130; // releaseCast melee after()
   export const BOW_RELEASE  = 120; // shot emit
   ```
   `world.ts:945`와 `1171`은 이 상수를 쓴다(값 불변).
3. **포즈를 절대 ms로 바꾼다.** `hero.ts:170-199`의 `attack`을 `a = t/dur` 대신 접촉 시각 `c` 기준으로 쓴다. 준비 `[0, 0.65c]`, 타격 `[0.65c, 1.1c]`(c에서 칼날/창끝/카타르가 정면 90°), 복귀 `[1.1c, lock]`이다. `lock = min(320, delay×0.8)`을 `Pose`에 넘겨(`field.ts:852`의 `dur` 대신 `lock`) 복귀가 잠금 안에서 끝나게 한다. 활은 당기기 `[0, BOW_RELEASE]`, 놓기 직후 반동 60ms다.
4. **활 발사 시각을 옮긴다.** `normalAttack` ranged(`world.ts:934-942`)를 `this.after(BOW_RELEASE, () => { emit shot; this.after(fly, resolve) })`로 바꾼다(+60 제거). `arrow` 소리는 발사 시각에 낸다. `atkReady`는 그대로라 DPS도 그대로다. 이중 사격(`1196-1197`)도 `BOW_RELEASE + i×110`으로 맞춘다.
5. **근접 스킬 효과를 접촉으로 옮긴다.** `releaseCast` melee(`1156`)의 `emit skill`을 `after(SKILL_CONTACT)` 콜백 안, `resolvePhys` 바로 앞으로 옮긴다. 시작 때는 외침 말풍선(`1148`)만 둔다. 음속 연격 흔들림(`1168`)은 마지막 합계 시각으로 옮긴다.
6. **검증:** `tools/lineup.html`이나 dev 훅 `__step(16, n)`으로 0–350ms를 16ms 간격으로 찍는다. 숫자 첫 프레임에 칼날이 대상 쪽을 향하는지, 활은 화살이 놓는 프레임 다음에 나가는지 본다. 숨긴 패널은 rAF가 멈추므로 `__step` 뒤에 화면을 찍는다.
7. **위험:** 무기별 포즈 회귀가 생길 수 있다. 2차 직업의 연출(`sonic` 등)은 그대로 두고 시각만 맞춘다.

### Top 2. 보상 경로가 '수치 변화'에서 끊기고, 줍기 전 이동하면 보상이 사라진다

- **안전성:** 지급은 줍기 시점(`world.ts:1890`)인데, `setZone`(`198`)과 앱 종료가 바닥을 지운다. 그래서 카드가 '획득!!' 배너, 도감, `totals.cards`는 처리됐는데 가방에는 없을 수 있다.
- **전달:** 획득물은 영웅까지 날아간 뒤 아무 수치도 바뀌지 않는다. 자동 판매는 제니가 조용히 오른다.

구현 스케치:

1. **실제 값을 즉시 지급한다(권장).** `rollDrops`에서 `GroundItem`을 만들고 바로 `this.grant(g)`를 부른다. `grant`는 `groundTick`의 `addItem`/자동 판매/로그 블록(`1885-1894`)을 옮겨 온 것이다. `g.granted = true`로 둔다. `groundTick`은 `pickup` 이벤트만 낸다(연출 전용). 이러면 `setZone`이 바닥을 지워도 손실이 없다.
   - 최소 수정안: `World.flushGround()`(미수거 전부 지급)를 `setZone` 앞, `game.ts` `pagehide`/`visibilitychange` 저장 앞에서 부른다.
2. **이벤트에 실제 결과를 싣는다.** `pickup`을 `{ t:'pickup', gid, to, id, n, zeny? }`로 넓힌다(연출 코드가 다시 계산하지 않게, 가이드 7장).
3. **도착 시점에 표시한다.** 렌더러 `handle('pickup')`에서 `this.later(380, () => this.onLoot(e, screenXY))`를 건다. `onLoot`은 아래처럼 나눈다.
   - 일반: 영웅 머리 위에 작은 아이콘 + `×n` 태그. 영웅마다 1초 묶음, 최대 2줄.
   - 자동 판매: 금색 `+Nz`가 상단 제니로 날아간다. `Hud.tsx:19`에 `key={zenyPulse}`와 CSS 펄스를 달고 400ms 카운트업한다. `zeny` 소리를 쓴다.
   - 장비: 파란 이름 태그를 띄우고, 더 좋으면 '추천▲' 토스트를 낸다.
   - 카드(절정): 배너 '획득!'(지금 `world.ts:1866`에서 옮김), 80ms 정지(Top 3의 `hitstop`), 카드 아이콘이 카드 탭으로 날아가고 '새' 배지가 붙는다.
   - 처치 시점에는 빛기둥과 기대감 소리만 남긴다. `1895`의 삼항식은 카드면 `card` 계열 소리로 고친다.
4. **위험:** 즉시 지급하면 가방 패널을 열어 둔 상태에서 숫자가 연출보다 ~1s 먼저 오른다. 허용 범위로 판단한다. 오프라인 보상(`offline.ts`)은 영향이 없다.

### Top 3. 강도가 뒤집혔다 — 자주 나오는 치명타·강타·범위 스킬이 화면 전체 섬광·흔들림을 쓰고, 보스 최후 타격에는 정지·여운이 없다. lowFx로 흔들림·섬광을 끌 수 없다

- **흔들림·섬광이 흩어진 곳:** 렌더러 `field.ts:244`, `254`, `309-310`, `390`, `486`, `538`, `572`, `613`과 월드 `shake` 이벤트 `world.ts:398`, `1168`, `1235`, `1694`, `1709`, `1771`이다.
- **lowFx가 줄이는 것:** 파티클 수(`288`)와 환경광(`785-787`)·잉크 외곽선(`856`, `885`)뿐이다.

구현 스케치:

1. 렌더러에 `kick(tier: 'frequent' | 'decision' | 'climax', opts)` 함수 하나를 두고 모든 `this.shake =`·`this.flash =`를 이것으로 바꾼다. 4장 표의 값을 쓰고, 등급별로 흔들림 쿨다운을 둔다(판단 600ms).
2. **국소 정지(판단 등급):** `stopUntil: Map<uid, t>`를 둔다. `drawMobUnit`/`drawHeroUnit`은 정지 중 포즈 시간을 멈추고 흰 플래시를 씌운다. 시뮬은 멈추지 않는다.
3. **전역 정지(절정 등급):** `Game.loop`(`game.ts:106-122`)에서 `now < hitstopUntil`이면 `world.advance`를 건너뛰고, 렌더러는 시계를 멈춘 채 다시 그린다. 그동안 `lastT`는 계속 갱신한다(따라잡지 않음). 방치형 싱글이라 정지 동안 게임 시간이 흐르지 않아도 공정성 문제가 없다. 사냥 속도 통계도 시뮬 ms 기준이라 왜곡이 없다.
4. 보스 `die`(`field.ts:244`)는 `kick('climax')`과 정지 120ms를 쓴다. 보스 시체 제거는 `CORPSE_MS`를 보스만 1600으로 하고(`world.ts:283`) 드롭 생성 위치·시각은 그대로 둔다.
5. lowFx(또는 새 설정 '화면 흔들림·번쩍임 끄기')에서는 `kick`이 흔들림·섬광·정지를 0으로 만든다. `matchMedia('(prefers-reduced-motion: reduce)')`이면 처음부터 켜 둔다.

### Top 4. 지원 사건의 문법 — 흡수·회복·지속 피해·버프가 피해와 구분되지 않거나 화면에 남지 않는다

### Top 5. 성장 입력이 '달라진 효과'를 보여 주지 않고, 스탯 미리보기가 +5/+10 단계와 어긋난다

구현 스케치:

1. **스탯 미리보기를 단계 기준으로.** `prevOf(k)`를 `h`의 얕은 복사본(`{...h, stats: {...h.stats}}`)에 `raiseStat(copy, k, step)`을 돌려 계산하고 '▶ +5포인트: ATK +9 · HIT +5'로 보여 준다. 실제로 올라갈 포인트 수 `n`도 같이 보여 준다(포인트 부족 시 부분 상승).
2. **누른 뒤 반응.**
   - `onUp`에서 `before = computeDerived(...)`를 기록하고, 올린 다음 `after`와 비교한다.
   - `lastBump = { k, deltas, t }` 상태를 둔다. `.stat-val.bump`과 바뀐 `.dv`에 0.8s 하이라이트(CSS keyframe)와 '+Δ' 작은 글자를 붙인다.
   - 소리는 `joblevel` 짧은 버전을 쓰거나 새 키를 만든다.
3. **카드 꽂기.** `doCompound`(`Cards.tsx:51-62`)에서 꽂기 전·후 `bonusLines(total)`을 비교한다. 바뀐 줄과 채운 `cslot`에 `.bump`를 붙인다.
4. **상점.** `quickBuy`(`Shop.tsx:92-97`)에서 `bumpId = d.id`로 행 하이라이트와 '보유' 펄스를 준다. 상단 제니 카운트다운은 Top 2의 제니 펄스와 공용으로 쓴다.
5. **공통 입력 상태.** `.nav button:active`, 공통 `:focus-visible`, `.btn:hover`를 넣는다. 가이드 7장에 따라 PC와 모바일을 따로 확인한다.

## 5. 이미 잘 되는 것 (다시 만들지 말 것)

- **몹 근접 공격의 접촉 정렬.** 판정 250ms가 돌진 정점(190ms) 근처다(`world.ts:1625`, `monster.ts:74`). 아군 붉은 틴트, 경직, 발톱, 빨간 숫자가 한 시점에 모인다.
- **보스 기술의 준비 → 실행 → 접촉.** 내려찍기·뿌리는 900ms 텔레그래프 원이 차오른다. 돌진은 대상 표시 → 돌진 → 도착 판정 → 넉백으로 이어진다(`world.ts:1682-1779`). 가이드가 말하는 '판단이 필요한 순간'의 좋은 예다.
- **볼트형 마법의 충돌·숫자 정렬.** 파이어·콜드 볼트(≈80ms 이내)와 소울 스트라이크(≈20ms)다. 시전 단서도 좋다: 원소색 마법진, 시전 바, 발동 외침(`field.ts:1114`, `world.ts:1148`).
- **RO풍 대미지 폰트.** 치명타 별 버스트, MISS, LUCKY, 다단 히트 뒤 노란 합계, 같은 대상 숫자 쌓기(260ms 안 좌우 엇갈림)가 있다(`dmgfont.ts`, `field.ts:211-220`).
- **힐 스킬의 문법.** 녹색 기둥과 흰 십자, 회복음이다. 붉은 충격·넉백·공격음을 재사용하지 않는다(`field.ts:618-637`).
- **몹 사망의 종료 상태.** 대기 자세로 남지 않고 0.9s 페이드·기울기(젤리는 납작)로 끝나며, HP 바가 숨는다. 다음 스폰과 겹쳐 빈 대기가 없다.
- **드롭 발생 연출.** 시체에서 포물선으로 튀어나오고(420ms), 장비는 파란 광, 카드·MVP는 금색 빛기둥이다. 카드는 바닥에 +0.9s 더 머문다(기대감 만들기).
- **레벨업 묶음.** 빛기둥, 날개, 링, 'LEVEL UP', 별, 전용 소리가 나오고 Base/Job 색이 갈린다. 레일 '+N'과 스킬 탭 배지가 '이제 무엇을 할 수 있나'로 이어진다. 전직 가능 배지(초보자)와 전직 연출도 같다.
- **아군 사망·부활 대기.** 누운 자세, '부활 Ns' 카운트다운, 레일 회색 + '부활 대기'가 있다.
- **퀵슬롯.** 눌림, 팝(수동·자동 모두), hot, 개수, 품절 회색, 오류 토스트, 버프 남은 시간 링이 있다. 자동 사용도 슬롯이 반응해서 '누가 썼나'가 읽힌다.
- **입력 확인 장치.** 되돌릴 수 없는 행동(카드 꽂기, 봉인 바치기, 귀한 물건 판매)에 확인 모달이 뜬다. 정련은 망치 3회 → 결과 연출이고 +7 이상은 배너가 뜬다.
- **스탯 창의 사전 예측(1포인트 기준).** '▶ ATK +2 · HIT +1', 비용, 길게 눌러 반복, 비활성 상태가 있다. 상점은 '추천▲', '보유 N', 가격 부족 빨강, 버튼 비활성이 있다.
- **보스 흐름.** 게이지 → 소환 버튼 깜빡임 → 출현 배너, BGM 전환, 오라·[BOSS]/[MVP] 라벨 → 처치 배너, 새 사냥터 개방 배너로 이어진다.
- **정리 위생.** 효과·파티클(≤900)·숫자(≤90)·말풍선을 수명 끝에 정리하고, 지역 이동 때 렌더 상태를 초기화한다(`field.ts:134-...`). 소리는 키별 최소 간격과 14음 상한이 있다(`audio.ts:84-86`).
- **lowFx가 핵심 정보를 지운다는 문제는 없다.** 숫자, HP 바, 텔레그래프, 배너는 유지되고 파티클·환경광만 준다. 남은 것은 흔들림·섬광을 줄이는 기능이다(Top 3).
