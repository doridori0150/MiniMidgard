## 3. B를 막는 실제 잔여 문제

### 3-1. 사망한 선택 영웅의 머리가 띠 위로 잘림 — P1

근거: `src/render/field.ts:743–751`, `:958–979`; `src/render/sprite.ts:138–155`, `:165–171`; `src/assets/frames/manifest.json`의 `dead_0`.

카메라와 화면 밖 집계는 서로 같은 box를 쓰지만, **그 box와 실제 그림이 같아진 것은 아니다.** 사망 box는 여전히 `x±40`, `y−36…y+24`다.

재현 조건은 390×106 관찰 캔버스, `(500,500)`의 선택된 사망 영웅, novice 또는 swordsman, 남성 헤어 `02`, 해당 영웅만 프레이밍하는 상태다. 단독 파티의 사망이나 다른 영웅도 모두 사망한 상태에서 성립한다.

1. 실제 `observeCamera()` 결과는 카메라 `(500,494)`, 줌 **1.5**다. 고정 box의 화면 상하단은 **8/98px**로 정상이다.
2. `dead_0`의 목 위치 `[440,596]`, 회전 `−55°`, 머리 pivot `[230,376]`, 원점 `[400,725]`, 축척 `76/620`을 적용한다.
3. `hair/male02.png`의 알파 128 이상 픽셀 상단은 발 원점 기준 **−45.501**이다. 화면 y는 `53 + ((500−45.501)−494)×1.5 = −6.251px`다.

즉 **눈에 보이는 머리 픽셀이 약 6.25px 잘린다.** 투명 여백이나 가상의 큰 장비를 가정한 지적이 아니다. 좌우 반전은 이 y 결과를 바꾸지 않는다. 기존 이동 반례가 해결됐다는 사실과 이 사망 반례는 분리해서 인정한다.

**완료 조건:** 현재 렌더 분기의 포즈·외형 경계 또는 해당 자산에서 검증한 보수적 경계를 카메라/집계에 함께 제공한다. 선택 사망자→부활, 선택 변경, 이동 중에도 8px 여백을 확인한다. 이번 반례의 상수 하나만 늘리고 전체 외형 계약을 PASS로 기록하지 않는다.

### 3-2. 퀵슬롯은 최소 입력 계약을 아직 충족하지 않음 — P1

근거: `src/styles.css:450–454`; `src/ui/QuickBar.tsx:45–72`, `:87`, `:161`.

- **설정 버튼:** `.qedit`는 **30×30px**, `flex:none`이며 다른 하한 규칙으로 보정되지 않는다. AUTO 스위치의 공식 진입 버튼인데 44×44 계약에 못 미친다. 제공된 사냥 스크린샷에서도 작은 설정 버튼이 남아 있다.
- **키보드 소비:** 아이템이 채워진 `QSlot`에는 `onPointerDown/up/leave/cancel/contextMenu`만 있다. Enter/Space의 버튼 활성화인 click으로 `useQuick()`을 실행할 경로가 없다. 실제 소스의 반환 버튼 속성을 실행 검사했을 때 click 소비 호출은 **0회**였다. 빈 슬롯 등록과 설정 버튼의 `onClick`이 있다는 사실로 채워진 슬롯의 소비 접근성을 대신할 수 없다.
- **오소비 안내:** 설정 창 마지막 문구는 아직 “슬롯 위 AUTO 표시를 눌러 자동 사용을 켜고 끌 수 있어요”다. 이제 그 span은 `pointer-events:none`이고, 입력은 소비 버튼의 pointer 핸들러로 간다. 안내대로 AUTO를 누르면 자동 설정을 바꾸는 대신, 사용 가능한 상황에서 **아이템을 소비한다**. 단순한 옛 명칭이 아니라 잘못된 행동을 유도하는 안내다.

**완료 조건:** 설정 버튼의 실제 타깃을 44×44 이상으로 만들고, 포인터·Enter·Space·보조기술 click이 공통 소비 경로를 정확히 한 번 실행하게 한다. 길게 누르기는 설정만 열고 소비하지 않아야 한다. AUTO 안내는 새 행 스위치 위치와 일치시킨다. 이 수정은 B의 퀵바 빈 칸 접기/편집 개편과 별개다.

### 3-3. 영웅 방향키 선택과 실제 포커스가 어긋남 — P2

근거: `src/ui/widgets.tsx:187–200`.

`props.onSel(n)`은 즉시 실행하지만, 포커스는 다음 프레임에서 `e.currentTarget`으로 찾는다. Preact의 이벤트 프록시는 여기서 원본 이벤트를 전달하며, 이벤트 dispatch가 끝나면 `currentTarget`은 null이다. 따라서 optional chaining으로 focus 호출이 생략된다.

실제 핸들러를 Node `EventTarget`으로 dispatch한 뒤 예약된 프레임을 실행한 결과는 **`selected=1`, `focusCalls=0`**이었다. 이 검사는 브라우저 DOM 검수가 아니라 이벤트 수명·핸들러 재현이다.

사용자는 영웅 A에 포커스를 둔 채 오른쪽 키로 편집 대상을 B로 바꾼다. 포커스는 A에 남고 A의 `tabIndex`는 −1로 바뀐다. 이어 Space/Enter로 A의 버튼을 활성화하면 대상이 다시 A가 되는 경로가 생긴다. 대상과 포커스의 일치는 이번에 도입한 roving radio 계약의 핵심이다.

**완료 조건:** 이벤트 처리 중 그룹 DOM을 지역 변수로 잡거나 ref로 참조하고, 선택된 라디오로 포커스를 이동한다. 오른쪽/왼쪽·위/아래, 끝에서 순환, 이후 Space와 Tab을 실제 입력으로 확인한다. 내부 탭의 `getElementById()` 방식은 이 결함과 별개다.

## 4. 31/31의 인정 범위와 다음 재검수

31개 PASS는 유효한 회귀 증거다. 특히 실제 Back 세 경로, 선행 스킬 현재/필요, 포인트 유무에 따른 상태, 접힘 복원이 추가됐다. 다음 누락 때문에 전체 인수로 확대할 수는 없다.

- **카메라 검사:** `ui-check.html:119`는 실제 자산 경계 대신 `y−90`, `y+8` 두 점을 한 시점에 검사한다. 40프레임을 진행하지만 각 프레임에서 단언하지 않으며, 사망/부활 상태도 만들지 않는다. §3-1을 잡는 검사가 아니다.
- **터치 검사:** `:132`의 선택자는 `.page button, .hud button, .nav button`이다. 사냥 필드의 `.qedit`, 모달 컨트롤, 버튼이 아닌 조작 요소는 포함하지 않는다. 가방의 소비/기타/카드 세부 탭과 서비스 내부를 모두 여는 루프도 없다. 기본 QA에는 보유 카드가 없어 카드가 있는 상태의 조작을 대표하지 않는다.
- **입력·단일 실행:** 프로그램 방식 `.click()` 중심이며 퀵바 소비, 키보드 포커스, 카드 삽입 수량을 검증하지 않는다. 포커스 trap/복귀·부모 스크롤·필터 검수도 그대로 남는다.
- **크기 경계:** 기본 390×844 및 높이 600→844 검사다. 제공된 360×800 정지 화면은 인정하되, 500×900 전체 메뉴, 320px, 200% 글자 확대, 긴 이름·다중 슬롯·safe-area 인수까지 뜻하지 않는다.

글자 계약도 “모든 필수 설명이 12px”으로 종료하면 안 된다. 카드 효과 `.crow-fx`는 **10.5px**, 카드 필터 `.fchip`과 프리셋 설명은 **11px**다(`styles.css:777`, `:788`, `:947`). 모달 제목은 이번에 **14px**로 개선됐지만 R2의 제목 토큰은 16px다(`:965`). 필수 효과·조건의 하한은 §4-2 잔여로 기록하며, 모달 제목의 2px 차이만을 독립적인 No-go 근거로 삼지는 않는다. 제목/영웅 행도 여전히 고정 높이여서 확대 지원 완료 선언에는 실제 배치 검수가 필요하다.

다음 재검수는 **§3의 세 재현을 우선 수정·검증**하고, 보유 카드/슬롯 장비/소비 아이템이 있는 QA 상태에서 관련 입력·하한·복귀 검사를 보강하면 된다. 기존에 통과한 보간, 정보 행 스크롤, 일반 상세 Back, ID 대상, 선행 수치 작업을 다시 설계할 필요는 없다.

**최종: No-go 유지.** 이번에는 B 착수 순서를 승인하지 않는다. `doing` 정확성, 사냥 레일·보스 정보, 퀵바 빈 칸 접기, 프리셋 차이, 파티 힐/자동 스킬, 스탯 실제 구매량·추천안 미리보기는 계속 B 범위이며, 아직 없다는 이유로 A 차단 목록에 추가하지 않는다.
