# Codex 2라운드 — 반론 답변과 Phase A 확정 사양

작성: Codex · 2026-10-07 · 구현 전 검토

**카드 독립 탭, 왼쪽 파티 레일, 접을 수 있는 라이브 필드 띠를 채택한다.** 최종 주 메뉴는 **사냥 / 파티 / 성장 / 장비 / 카드 / 탐험**이다. 다만 150px 띠에서 흩어진 파티 전원을 항상 읽을 수 있다는 보장은 수정한다. 기본은 파티 전체 프레이밍, 과도하게 흩어진 경우는 선택 영웅 관찰과 화면 밖 인원 표시다.

검토 근거는 [Codex R1](codex_r1.md), [Claude R1](claude_r1.md), [Claude R2](claude_r2.md), 현재 `src/ui`와 `src/styles.css`다. 카메라·행동·학습 판정은 연결된 `src/render/field.ts`, `src/game/world.ts`, `src/game/state.ts`도 확인했다. 아래 수치는 CSS px이며 새 설계값이다. 구현·실기기 검증 완료를 뜻하지 않는다. 현재 소스는 R1보다 진행되어 있으므로 줄 번호보다 파일과 심벌을 기준으로 삼는다. Claude가 전달한 과거 사용자 요구는 이번 토론의 제약으로 수용한다.

## 1. Claude의 세 반론에 대한 판단

### 1-1. 카드 독립 탭 — 수용

R1의 성장 내부 카드 배치를 철회한다. 카드 전용 탭을 요청했다는 사용자 요구가 있고, 카드가 파티 공용 수집품이라는 점에서도 캐릭터별 스탯·스킬과 분리하는 편이 일관된다. `Cards.tsx`는 이미 슬롯 관리·보유 카드·도감을 묶고 `insertableCards()`로 실제 삽입 가능성을 판정한다. 이를 유지하는 비용도 작다.

6탭은 390px에서 각 65px, 360px에서 각 60px를 확보할 수 있다. 44px 터치 목표를 충족하므로 탭 수만으로 반대할 이유는 없다. 대신 스킬 포인트 합계처럼 큰 숫자 배지는 없애고, 장비 안의 착용·의상·가방을 한 단계로 정리한다. 카드 목록의 원본은 카드 화면 하나로 두며 가방의 카드 항목은 해당 화면으로 연결한다.

### 1-2. 왼쪽 세로 파티 레일 유지 — 수용

R1의 필드 상단 가로 3인 요약 시안을 철회한다. 초상 정보를 좌우에 두라는 사용자 요구를 따른다. `Hud.tsx/PartyRail`의 초상·HP/SP·버프·사망 표현과 초상→해당 영웅 성장 경로를 보존한다.

다이어트는 B에서 한다. 직업명·Job·EXP의 중복은 상세로 보내고 이름·Lv·HP/SP·버프·현재 행동을 남긴다. 기존 `.prail` 폭 132px를 무조건 작은 고정폭으로 줄이지 않는다. 12px 행동 문구와 10자 이름이 함께 들어가는지 확인한 뒤 폭을 정한다. A에서는 위치·정보 구조를 유지하면서 터치 크기와 행동 가능 배지만 바로잡는다.

관리 화면의 가로 초상 선택 줄은 이 반론과 충돌하지 않는다. 필드 HUD가 아니라 편집 대상을 고르는 컨트롤이며, 이때 필드 레일은 숨긴다. 같은 화면에 두 선택기를 동시에 노출하지 않는다.

### 1-3. 관리 화면의 라이브 띠 — 수정 수용

전투 관찰의 가치를 인정하며, 일반 관리·파티 모두 첫 진입은 펼침으로 한다. 사용자가 접으면 다음 진입에도 그 선택을 존중한다. 파티에 들어갈 때마다 강제로 펼치지는 않는다.

다만 **150px만 확보하면 전원 전신이 보인다**는 부분은 받아들이지 않는다. `FieldView.tsx`는 현재 시트 높이를 60%/78%로 추정해 `insetBottom`을 넘기고, `FieldRenderer.resize()`는 줌을 최소 1로 제한한다. 카메라는 `World.center()`의 생존 파티 평균 위치를 따라갈 뿐 전원의 스프라이트 경계를 맞추지 않는다. 전열·후열·자유 추격을 모두 150px에 강제로 넣으면 지나친 축소가 필요하다.

채택할 계약은 다음과 같다.

- 펼침 **총 150px = 상태·접기 행 44px + 실제 라이브 캔버스 106px**. 접힘은 상태 행 44px만 남긴다. 접힘으로 본문 106px를 회수한다.
- 모일 때는 전원을 프레이밍한다. 흩어져 읽기 어려워지면 선택 영웅의 전신을 우선하고 `화면 밖 동료 n명`을 표시한다. 전원 동시 관찰은 하단 `사냥`으로 이동한다.
- 띠 전체에서 접기/펼치기는 가능하지만, 관리 중에는 몬스터 집중 공격·NPC 클릭이 발생하지 않는다. 상태 행과 캔버스를 각각 같은 토글 동작의 형제 버튼으로 구성하며 중첩 버튼을 만들지 않는다.
- 선택 영웅이 잘리는 문제를 CSS 가림이나 파티 배치 변경으로 해결하지 않는다. 렌더러의 관찰 모드가 A의 필수 의존성이다.

## 2. 남아 있던 질문과 사실관계 정리

| 쟁점 | 최종 답변·처리 |
|---|---|
| AI 이유를 단계적으로 넣을 것인가 | 현재 `HeroUnit.doing`, `heroTick`, `trySupport`, `tryRest`, `position`, `idleFollow`에 행동 문구가 이미 있다. 별도의 추정 라벨 1차는 만들지 않고 B에서 이 값을 연결한다. 다만 엔진에 있다는 사실만으로 모든 문구가 완전하다고 판정하지 않는다. 공격 쿨 대기·추격·시전 취소·죽음/부활 시점에 이전 문구가 남는지 분기별로 검증한다. |
| 힐·공격 정책의 순서 | 부활→힐→버프→휴식→대상 선정→도발→CC→공격 스킬→평타라는 큰 순서는 수용한다. 단, 아래의 정확한 조건을 사용한다. |
| 카드 주 메뉴 | 독립 유지. 가방은 장비에 통합한다. |
| 장비 점수 | 단일 `추천▲` 대신 실제 항목별 변화. C에서 `equip`의 동료 이전·두손 무기·액세서리 대상 처리를 복제 상태에 적용하고 `computeDerived`로 계산해 실제 장착과 같은 경로를 쓴다. 상점도 같은 비교 결과를 사용한다. |
| 미발견 도감 | `zoneKnown(s,z)`를 공통 기준으로 한다. 미방문 일반 맵까지 모두 숨기는 규칙은 아니다. 이 함수는 숨겨진 맵의 발견·해금 여부를 구분한다. 이미 보유/발견한 카드 또는 공개 맵에서도 나오는 몬스터의 정체는 유지하되, 그 카드의 숨겨진 출현 장소는 가린다. 미발견 맵 전용 몬스터·카드의 이름·효과·확률·상세 링크를 `???`에서 유출하지 않는다. 발견했지만 봉인된 맵은 기존 `gateLines` 공개 범위를 따른다. C에서 도감과 역방향 링크를 함께 수정한다. |
| 스탯 부분 구매 | 가능한 만큼 구매하는 `raiseStat` 계약 유지. 복제 영웅에 적용한 반환값 `n`과 포인트 차이로 `+n (총 p점)`을 표시한다. 구매량 0이면 소비 불가. 총비용·추천안 미리보기는 B, 행동 가능 배지는 A다. |
| 오프라인 데이터 | 확장 방향에 동의한다. 현재 `load()`는 v1 검사와 누락값 보완 방식이므로 범용 마이그레이션이 이미 완성된 것으로 보지는 않는다. D에서 선택 필드와 구세이브 기본값을 명시한다. 실제 부재 시간·시작/종료 레벨·획득 장비 UID·구간별 사냥터는 계산 시 기록한다. 옛 보고에서 역산하지 않는다. |
| 화면·폰트 | 390×844 기준, 360×800 필수. Galmuri 유지, 본문 14px·설명 12px·제목 16px로 확정한다. 320px는 경계 검사다. |
| 경고 빈도·실측 | Claude의 기본 파티 휴식 7~25%는 보고된 결과로 받아들이되 이번 검토에서 재측정한 값은 아니다. 보스 실패·포션 품절 빈도는 미확인이다. B 검수에서 신규/중반/힐러 없는 파티를 나눠 측정하고, 그전에는 반복 경고 강도나 시간당 효율 수치를 새로 정하지 않는다. |

힐 설명에는 두 가지 정정이 필요하다. `trySupport()`에서 전투·탱커 역할은 자신 `min(설정값,60)%`, 동료 `min(설정값,45)%` **미만**일 때 후보가 된다. 고정 60%/45%가 아니다. HP 35% 미만 예외는 “회복량의 60% 이상 손실” 조건만 면제한다. 설정 임계값·거리·자동 사용·SP·쿨다운까지 무시하고 즉시 힐하는 예외가 아니다. `first_aid`는 별도 자기 회복 규칙을 따른다.

`enabledSkills()`는 카드 부여 스킬을 합치고 영웅이 배운 더 높은 레벨을 우선하며, `auto.skills[id] === false`는 양쪽 모두에 적용한다. `chooseSkill()`의 SP 50% 절약 조건은 언데드 공격용 힐에도 적용하지만 지원 힐·부활·버프·CC는 그 분기 밖이다. B의 파티 설정과 도움말은 이 차이를 반영한다. 현재 `doing`의 `SP 절약` 문구도 모든 보류 원인의 상세 증명으로 확대 해석하지 않는다.

## 4. Phase A 구현 명세

### 4-1. 공통 셸과 390×844 높이 계약

`App.tsx/GameScreen`의 절대 배치 `.sheet`와 `tall` 분기를 제거하고 다음 순서의 흐름 레이아웃으로 바꾼다. 사냥에서는 HUD→전체 필드→하단 메뉴다. 관리에서는 HUD→라이브 띠→제목→필요한 영웅 선택→내부 탭→본문→하단 메뉴다. 각 패널이 자체 `Win` 제목·영웅 탭·스크롤을 다시 만드는 구조를 해체하고 셸이 한 번만 제공한다. 모달의 `Win`은 유지한다.

아래 표는 **safe-area 0, 기본 글자 크기, 영웅 선택이 있는 관리 페이지** 기준이다. 모든 높이는 테두리·패딩 포함이다.

| 영역 | 펼침 높이 | 펼침 y 구간 | 접힘 높이 | 접힘 y 구간 |
|---|---:|---|---:|---|
| HUD | 48 | 0–48 | 48 | 0–48 |
| 라이브 띠 | 150 | 48–198 | 44 | 48–92 |
| 페이지 제목 | 48 | 198–246 | 48 | 92–140 |
| 영웅 선택 | 56 | 246–302 | 56 | 140–196 |
| 내부 탭 | 44 | 302–346 | 44 | 196–240 |
| 본문 스크롤 뷰포트 | 442 | 346–788 | 548 | 240–788 |
| 하단 6탭 | 56 | 788–844 | 56 | 788–844 |

본문의 위아래 패딩 각 12px는 위 높이 안에 포함된다. 영웅 선택이 없는 화면은 그 56px를 본문에 돌려준다. 내부 탭이 없는 설정은 추가 44px도 돌려준다. 사냥 필드는 `844−48−56 = 740px`이며 필드 내 컨트롤은 그 안에 배치한다.

- `H=실제 100dvh`, `T/B=env(safe-area-inset-top/bottom)`라 두면, 영웅 선택 관리 화면 본문은 `H−T−B−48−L−48−56−44−56`이다. `L`은 150 또는 44다.
- top safe-area는 HUD 바깥의 같은 배경, bottom safe-area는 하단 메뉴 아래의 같은 배경으로 한 번씩만 소비한다. 56px 버튼 높이 안에 bottom 패딩을 넣어 버튼을 줄이지 않는다. 예를 들어 H=844, T=47, B=34이면 펼친 본문은 361px다. 기기마다 inset이 같다고 가정하지 않는다.
- `.app`의 `max-width:480px`, 푸른 창틀·밝은 본문은 유지한다. 본문은 `minmax(0,1fr)`/`min-height:0; overflow-y:auto`, 나머지는 축소되지 않는 행으로 구성한다. 페이지 최상위에 세로 스크롤은 하나만 둔다.
- HUD에는 지역·제니·44×44 설정 버튼을 둔다. 파티 버튼은 하단과 중복되므로 제거한다. 지역 버튼은 탐험/지도에 명시적으로 진입한다. 제니는 본문 14px, 긴 수치는 HUD에서 축약하고 가방/상점에서 정확한 값을 제공한다.
- 제목 행은 16px 제목과 오른쪽 44×44 `사냥으로 돌아가기` 버튼. 하위 상세에서는 왼쪽 44×44 뒤로가기를 추가한다. 스킬 포인트·파티 평균 레벨처럼 길어지는 보조 값은 제목줄에 억지로 넣지 않고 본문 첫 줄로 옮긴다.

### 4-2. 탭과 기존 패널 매핑

| 주 메뉴 | A의 내부 탭·초기값 | 재사용할 코드·영웅 선택 |
|---|---|---|
| 사냥 | 내부 탭 없음 | `FieldView`, 왼쪽 `PartyRail`, 퀵바·미니맵. 관리 선택 줄 없음. |
| 파티 | **작전** / 파티원 | `PartyPanel`의 프리셋·orders를 작전으로, 개별 전술을 파티원으로 분리. 작전은 공용이므로 선택 줄 없음. 파티원은 선택한 한 명의 전술을 표시하며 선택 줄 있음. |
| 성장 | **스탯** / 스킬 | `StatusPanel` / `SkillsPanel`. 양쪽 모두 선택 줄 있음. |
| 장비 | **착용** / 의상 / 가방 | `EquipPanel`의 equip/costume과 `BagPanel`. 착용·의상은 선택 줄 있음, 공용 가방은 없음. 기존 착용 안의 의상 탭을 또 중첩하지 않는다. |
| 카드 | **슬롯 관리** / 카드 도감 | 현 `CardPanel`의 두 탭 유지. 슬롯 관리에 보유 카드 목록도 유지하고 선택 줄 표시. 공용 도감은 선택 줄 없음. 상태별 진입/빈 화면 개선은 C다. |
| 탐험 | **지도** / 마을 서비스 | `MapPanel` / `TownPanel`. 공용 화면에는 선택 줄 없음. 미용실처럼 실제 영웅을 편집하는 하위 화면에만 같은 공통 선택 줄을 표시한다. |

굵은 항목은 저장된 세션 선택이 없을 때의 초기값이다. 같은 세션의 재진입은 마지막 내부 탭·필터·스크롤을 복원한다. 단 명시적 바로가기는 목적지를 우선한다. 예: 레일 초상→그 영웅의 성장/스탯, 기존 `openPanel('skills')`→성장/스킬, `openPanel('bag')`→장비/가방, `openTown('tool')`→탐험/마을 서비스/도구 상점. 기존 안내의 `[스킬]`, `[사냥터]` 등 명칭도 새 경로로 갱신한다.

가방의 장비/소비/기타는 본문 안의 44px 필터 행으로 유지한다. 카드 항목은 카드/슬롯 관리의 보유 목록으로 이동하는 바로가기이며 별도 카드 재고 UI를 만들지 않는다. 의상·가방에서도 기존 기능을 삭제하지 않는다. 설정은 일곱 번째 주 메뉴가 아니라 HUD에서 여는 보조 페이지이며, 닫으면 진입 전 페이지·선택·스크롤로 복귀한다.

하단 메뉴는 `<nav>`와 버튼으로 만들고 활성 페이지를 `aria-current="page"`로 표시한다. 내부 탭은 `tablist/tab/tabpanel` 및 `aria-selected`, 방향키 이동을 지원한다. **활성 주 메뉴를 다시 눌러도 닫지 않는다.** 현재 `openPanel()`의 같은 패널 토글 동작과 구분한다. 사냥 버튼만 관리 페이지에서 필드로 복귀한다. 탐험/마을 서비스 선택은 이동이나 휴식을 실행하지 않는다.

### 4-3. 영웅 선택 줄

`widgets.tsx/HeroTabs`의 이름 버튼을 공통 `HeroSelector`로 대체한다. 56px 행 안에 높이 48px 버튼을 놓고 위아래 4px 여백을 준다. 390px에서는 좌우 12px·간격 6px로 3인 버튼 폭이 각각 118px다. 초상 32×32, 이름 12px 한 줄, 선택 테두리와 표시를 사용한다. 10자 이름은 말줄임하되 접근 가능한 이름에는 전체 이름을 넣고 본문 대상 제목에서는 줄바꿈해 모두 보인다. HP/SP·직업·레벨을 선택기에 중복하지 않는다.

- 첫 선택은 첫 영웅, 이후 모든 영웅별 페이지에서 같은 선택을 공유한다. 1인 파티도 행을 유지해 편집 대상을 명확히 한다. 모집/잠긴 슬롯은 이 행에 추가하지 않고 파티 본문과 사냥 레일에 둔다.
- 원본 선택값은 **영웅 id**로 보존한다. 현재 `g.sel`은 인덱스이며 `PartyPanel.move()`는 순서 변경 시 이를 이동 대상 인덱스로 바꾼다. A에서 선택 메서드를 공통화하고 `g.sel`, `hero`, `heroUnit()`은 선택 id를 현재 배열에 해석하도록 맞춘다. 기존 인덱스 기반 호출은 경계에서 변환한다.
- 영웅을 바꾸면 다른 영웅의 장비 후보·카드 대상·스탯 bump·스킬 펼침이 남지 않도록 임시 선택을 초기화한다. 본문 스크롤은 `페이지/내부 탭/영웅 id`별로 복원하고 첫 방문은 맨 위다. 카드 선택 과정은 취소되지만 재고·장착은 바뀌지 않는다.
- 파티원 화면의 순서 변경 버튼은 선택 영웅의 위/아래 이동으로 유지하되 두 개의 44×44 버튼을 가로 배치한다. 순서가 바뀌어도 선택 id는 유지한다. `첫 번째가 리더`를 표시한다. 별도 리더 지정 동작은 B에서 정리한다.
- 명시적 버튼 선택을 기본으로 하고 **A에는 영웅 전환 스와이프를 넣지 않는다.** 가방 가로 필터·지도·세로 스크롤과의 충돌을 피하면서 모든 선택을 한 번의 탭으로 할 수 있다. 키보드 선택은 라디오 그룹에 준하는 좌우 이동·선택 상태를 제공한다.
- 모달의 장착 대상 선택은 예외적으로 모달 안에 하나만 둔다. 기존 `ItemModal`의 지역 `heroIdx`는 안정된 id로 바꾸고 모달을 닫으면 배경 선택을 유지한다. 배경 선택기는 모달 동안 조작할 수 없다.

### 4-4. 라이브 띠·카메라·접힘 기억

접힘 선호는 `일반 관리`와 `파티` 두 값으로 저장한다. 둘 다 최초 기본은 펼침이다. UI 전용 버전 키(예: `minimidgard.ui.v1`)의 `compactField.general/party`에 저장하고 세이브 게임 상태·`commit()`과 분리한다. 저장소 사용이 막히면 세션 메모리로 유지한다. QA 모드는 실제 선호값을 읽거나 덮어쓰지 않는다. 게임 초기화 때 UI 선호도 초기화한다.

- `일반 관리` 값은 성장·장비·카드·탐험·설정에서 공유한다. 파티의 작전/파티원은 `파티` 값을 공유한다. 탭 이동·영웅 변경·전투 시작·희귀 획득이 사용자의 접힘 선택을 뒤집지 않는다.
- 44px 상태 행은 `지역 · 사냥 진행`을 기본으로 하고 실제 마을이면 `마을`, `wipeUntil > 0`이면 `재정비 중`을 우선한다. `사냥 진행`은 자동 사냥 루프가 계속된다는 뜻이다. A에서 이를 `교전 중`, `힐 대기` 등으로 세분해 추정하지 않는다. 정확한 행동은 B에서 `doing`을 연결한다.
- 토글은 `aria-expanded`와 `aria-controls`를 제공한다. 접힘에도 상태와 전멸 정보는 남는다. 로그·보스 게이지·미니맵·레일·퀵바는 관리 띠에서 숨긴다. 큰 지역 배너나 전멸 베일로 106px 캔버스를 덮지 않는다. 카드 등 중요 알림은 공통 토스트에서 유지한다.
- `FieldView`의 메인 캔버스는 동일 인스턴스를 유지한다. 전환마다 `attachCanvas()`를 다시 호출하거나 두 번째 렌더러를 만들지 않는다. 접힘 시 캔버스는 레이아웃/포인터에서 제외한다. `Game.loop()`의 월드 진행과 렌더러 사건·사운드 소비는 유지한다. A에서는 접힘을 이유로 `renderer.frame()` 호출 자체를 끊어 사건을 쌓지 않는다. 0×0 측정값은 `resize()`에 반영하지 않고 마지막 유효 버퍼를 유지한다.
- `ResizeObserver`로 실제 캔버스 크기와 사냥 화면의 퀵바 점유 영역을 관찰한다. 관리 모드의 `insetBottom`은 0이며 60%/78%·고정 84px 보정은 제거한다. 사냥은 측정한 퀵바 여백을 쓴다. safe-area·글자 확대·주소창 변화에도 다시 측정한다.
- 렌더러에 `hunt/observe` 모드와 선택 영웅 id, 실제 뷰포트를 전달한다. observe에서는 캐릭터의 머리·장비·발까지 포함한 렌더링 경계 합집합을 구하고 사방 8px 여백 안에 맞춘다. 파티 전체 적합 줌이 0.75 이상이면 전체, 그보다 작아지면 선택 영웅 전신 적합 줌을 사용한다. 0.75는 A의 검수 시작값이며 읽기 어려우면 조정한다. 선택 영웅조차 큰 외형으로 넘치면 그 전신을 우선해 더 축소한다.
- 카메라 타깃은 실제 월드 좌표이며 인물을 별도 위치에 재배치하지 않는다. 모드 전환·부활 직후에는 경계를 즉시 맞추고 이후 보간해도 경계 밖으로 인물을 밀지 않는다. 맵 가장자리에서도 인물을 자르지 않도록 관찰 모드의 클램프를 조정한다. 화면 밖 인원 표시는 실제 화면 경계로 계산하고 캔버스 위 고정 텍스트로 두되 캐릭터 프레이밍에서 그 영역을 제외한다.
- 관찰 모드와 모달이 열린 동안 `FieldRenderer.onPointer()`를 차단한다. 현재 캔버스는 `pointerdown`에 월드 입력을 실행하므로 CSS 클릭 처리만 바꿔서는 접기 탭이 집중 공격/NPC 실행으로 새어나갈 수 있다. 사냥 모드 복귀 시에만 기존 월드 입력을 복원한다.

### 4-5. 스크롤·상세 스택·닫기

현재 `Game.modal`은 단일 값이고 `setModal()`이 이전 모달을 덮어쓴다. `WorldMap`의 선택 지역/맵, `TownPanel`의 서비스, 아이템 상세의 대상도 서로 다른 지역 상태다. A에서 이를 다음 계약으로 정리한다.

1. `game.ts`에 UI 전용 주 메뉴·내부 탭·선택 id·스크롤 상태와 상세 스택을 둔다. 게임 저장에 모달 콜백이나 DOM 포커스를 넣지 않는다. 기존 `openPanel`/`openTown` 호출은 새 목적지로 연결하는 어댑터로 유지한다.
2. 아이템→몬스터→드롭 아이템 등의 상세는 push, 뒤로/닫기/허용된 배경 탭은 한 장 pop이다. 반환 시 부모 필터·스크롤·대상을 복원한다. `confirm` 취소도 부모로 돌아가며, 확인은 해당 동작을 한 번만 실행한다. 판매·카드 삽입 뒤 부모 대상이 사라지거나 달라졌으면 갱신하거나 유효한 목록으로 복귀한다.
3. 기존 `setModal(null)`을 무조건 pop으로 일괄 치환하지 않는다. 확인창은 닫기와 실행 콜백이 각각 닫기를 호출할 수 있다. `pushDetail / popDetail / replaceDetail / closeDetails`의 의미를 나누고 각 호출을 점검한다. 새 모달이 떠도 기존 상세 인스턴스의 지역 상태를 보존하거나 명시적 상태 객체로 복원한다.
4. 뒤로가기/Escape 순서는 **최상위 모달 → 지도 상세/마을 서비스 하위 화면 → 설정의 진입 화면 → 관리 루트에서 사냥**이다. 선택만 한 장비/카드 후보가 있으면 상세를 닫기 전에 그 선택 취소가 우선한다. 관리 제목의 `사냥으로 돌아가기`와 하단 사냥은 이력을 순회하지 않고 사냥으로 간다.
5. 모달은 배경을 inert 처리하고 포커스를 가둔 뒤 닫을 때 트리거로 돌린다. 모달을 연 채 배경 하단 탭을 누를 수 없다. 오프라인 보고는 기존처럼 배경 클릭으로 사라지지 않으며 명시적 확인으로 닫는다. Escape도 이 확인 규칙을 우회하지 않는다.
6. 앱이 만든 상세/관리 이력은 브라우저 Back에도 같은 순서로 연결한다. push/pop과 `popstate`를 양방향 동기화하되 일반 렌더·180ms notify마다 이력을 추가하지 않는다. 주 메뉴 전환·내부 탭·선택 변경은 현재 관리 엔트리를 replace하고 상세 진입만 push한다. 앱 소유 사냥 루트 아래에서는 브라우저 이탈을 막거나 이력을 무한 보충하지 않는다.

지도는 예외적인 이중 세로 스크롤을 없앤다. 현재 `.wm-map {height:54%; min-height:250px}`와 `.zc-body {overflow-y:auto}` 대신, 하나의 본문 안에 `세계 지도 펼치기` 44px 버튼·펼친 지도 250px·지역 목록/상세를 흐름 배치한다. 세계 그림은 최초 접힘, 펼침 선택은 세션에서 기억한다. 그림·핀·지방 구조는 유지하고 지도 부분은 본문과 함께 스크롤된다. 가로 필터 스크롤은 허용하지만 세로 스크롤 컨테이너를 중첩하지 않는다.

### 4-6. 버튼·글자 토큰과 입력 계약

| 토큰/대상 | A 값 | 적용 방식 |
|---|---|---|
| `--touch-min` | 44px | 독립 버튼·닫기·칩·카드 슬롯·지도 핀의 실제 박스 가로/세로 최소값 |
| `--control-h` | 48px | 기본 텍스트 버튼, 라벨을 포함한 토글 행의 최소 높이 |
| `--text-body` / 행간 | 14px / 1.5 | Galmuri11, 본문·설정·버튼 |
| `--text-caption` / 행간 | 12px / 1.4 | 설명·탭 라벨·조건·배지. 필수 정보는 이보다 줄이지 않음 |
| `--text-title` / 행간 | 16px / 1.4 | 관리·모달 제목 |
| `--space-page` | 12px | 390px 본문 좌우 여백 |

| `--live-open-h / --live-closed-h` | 150px / 44px | 정상 높이 화면의 라이브 띠 |

글자 토큰은 기본 16px 기준 rem 값으로 선언해 사용자 글자 확대를 따른다. 고정 스프라이트·장식 숫자까지 무조건 확대하는 규칙은 아니지만 조작에 필요한 비용·수량·상태를 8~10px로 남겨두지 않는다. 200% 글자 확대 시 제목/선택/탭은 필요한 만큼 커지고 본문이 줄어드는 구조로 한다.

`.btn.sm/.xs`는 밀도·강조 차이만 남기고 터치 크기를 줄이지 않는다. `.win-title .x` 20×18, `.tb-btn` 32×28, `.toggle` 34×18, `.stat-btn` 40×40, `.cslot` 28×34 등을 직접 교체한다. 시각적 스위치 그림만 34×18로 남기는 것은 가능하지만 라벨과 함께 하나의 48px 행 버튼이고 `role="switch"`, `aria-checked`, 명확한 이름을 갖춰야 한다. 별도 버튼을 행 안에 중첩하지 않는다.

스킬 상세의 현재 이미지/div 클릭은 44px 이상 상세 버튼으로 바꾸고 학습·자동 사용과 분리한다. `StatusSkills.tsx/useHold`의 pointerdown 즉시 소비는 A에서 제거한다. A는 일반 click 한 번으로 선택 단계 한 묶음을 적용하고 길게 누르기 반복은 보류한다. 스크롤·pointercancel·화면 이탈이 소비로 이어지지 않으며 키보드로도 실행 가능해야 한다. 퀵바는 B의 시각 개편 전이라도 수동 소비/설정/AUTO의 터치 박스가 겹치지 않게 한다.

폼·설정·지도 핀·카드 슬롯의 실제 조작 영역을 검사한다. `.btn`만 키우고 다른 클래스와 inline font-size를 그대로 두면 A 완료가 아니다. `index.html`의 `maximum-scale=1,user-scalable=no`는 구현 때 제거해 확대를 허용해야 한다. 이는 UI/CSS 밖의 작은 필수 의존성이다.

### 4-7. 스킬 상태와 행동 가능 배지

`SkillsPanel`의 상태는 아래 우선순위로 판정한다. 실행 권한은 계속 `canLearn()`/`learnSkill()`이 최종 결정한다.

| 순서 | 상태·표시 | 동작 |
|---|---|---|
| 1 | 현재 레벨이 maxLv 이상 → `MAX` | 학습 불가, 상세 조회 가능 |
| 2 | 학습 대상 직업이 아님 → `학습 종료` | 전직 후 초보자 스킬 등. 모든 이전 직업을 잠그지 않는다. 현재 계보의 1차 스킬은 계속 학습 가능 |
| 3 | `!skillReqMet` → `선행 필요` | 상세에서 필요한 스킬의 현재/요구 레벨 표시 |
| 4 | `skillPts <= 0` → `포인트 부족` | 상세 조회 가능 |
| 5 | `canLearn` → `학습 +1` | 클릭 후 최신 상태로 재검증하고 1회 적용 |

MAX 등은 흐린 `+` 대신 읽을 수 있는 텍스트다. 상세 펼침은 항상 별도 버튼이며 색만으로 상태를 구분하지 않는다. 자동 사용은 학습된 자동 가능 액티브에 대해 기존 값 `auto.skills`를 그대로 편집하되 이름·켜짐/꺼짐을 표시한다. 파티로의 본격 통합은 B다. 전직은 `canJobChange()`의 반환값을 사용해 조건 문장을 한 번만 표시한다.

공통 UI 판정 함수로 다음 값을 계산해 레일·선택 줄·성장 내부 탭·하단 메뉴가 공유한다.

- `statReady(h) = STAT_KEYS.some(k => h.stats[k] < 99 && h.statPts >= statCost(h.stats[k]))`.
- `skillReady(h) = lineage(h.cls)의 skillsOf를 모아 some(sk => canLearn(h,sk.id))`.
- `jobReady(h) = !canJobChange(h)`.
- 하단 성장: 어느 영웅이든 전직 가능하면 `전직`, 아니면 stat/skillReady가 있을 때 점 배지. 포인트 합계 숫자는 표시하지 않는다. 배지는 별도 터치 대상이 아니다. 접근 가능한 이름에는 가능한 행동을 포함한다.
- 레일/선택 줄: 영웅별로 같은 우선순위를 적용해 포인트 1점이 전직을 가리지 않게 한다. 스탯/스킬 내부 탭은 해당 판정만 표시한다. 남은 포인트 수는 본문에서 항상 볼 수 있다.
- 카드: 기존 `s.totals.cards > (s.cardSeen ?? 0) && insertableCards(s) > 0` 유지. 숫자를 쓰면 장수가 아니라 삽입 가능한 **종류 수**임을 설명한다. 카드를 실제로 열었을 때 읽음 처리한다. 숨긴 패널을 미리 mount해 `CardPanel`의 mount effect가 읽음 처리하게 만들지 않는다.
- 사냥·파티·장비·탐험에는 A에서 새로운 추정 추천 배지를 만들지 않는다. 전직이 성장과 레일에 동시에 알려지는 것은 허용하되 연속 점멸은 없앤다.

### 4-8. 360px 및 작은 높이 대응

360×800, safe-area 0에서도 높이 토큰은 그대로다. 영웅 선택 관리 화면의 본문은 펼침 **398px**, 접힘 **504px**다. 폭 때문에 라이브 띠를 120px로 줄이거나 글자를 축소하지 않는다.

- 좌우 페이지 여백만 12→8px, 선택 버튼 간격은 6px 유지. 3인 선택 폭은 `(360−16−12)/3 ≈ 110.7px`, 하단 탭은 60px다. 실제 터치 폭을 유지한다.
- 내부 탭은 최대 3개이며 가로 전체를 나눠 쓴다. 가방/카드의 세부 필터만 가로 스크롤 허용. HUD 지역명과 영웅 이름은 말줄임, 조건·가격·효과는 줄바꿈한다. 버튼을 겹치거나 글자를 12px 아래로 줄이지 않는다.
- 파티의 5개 선택지가 한 줄에 안 들어가면 그룹을 다음 줄로 보내거나 3+2 그리드로 배치한다. 라벨 92px와 5개 버튼을 기존 `.ord-row`에 그대로 밀어 넣지 않는다. 프리셋은 2열, 긴 스킬은 상세/학습과 자동 사용을 두 행으로 나눈다.
- 카드 부위 이름·장비 이름·여러 카드 슬롯은 두 행 이상으로 배치해 `.cslot` 44px를 지킨다. 장비 인형 배치는 유지하되 부위 버튼의 이름은 줄바꿈하고 겹치면 행 높이를 늘린다. 상점 구매/판매 버튼도 별도 행으로 보낼 수 있다.
- 본문 뷰포트가 240px 미만이면 라이브 띠를 일시적으로 접어 작업 공간을 확보한다. 이는 작은 높이/글자 확대에 대한 레이아웃 처리이며 저장된 선호값은 바꾸지 않는다. 펼칠 공간이 없을 때는 상태 행에 `사냥 화면에서 보기`를 제공한다. 공간이 회복되면 저장된 선호대로 복원한다.
- 320px 경계에서도 44px와 12px 하한을 유지하고 내용은 줄바꿈/스크롤한다. 지원 여부를 실제 검수로 기록하며 360px 통과를 320px 통과로 대신하지 않는다.

A 인수 조건은 다음과 같다.

1. **레이아웃:** 같은 QA 저장본으로 390×844·360×800·500×900에서 모든 주 메뉴와 내부 탭을 비교한다. 표의 기본 높이, safe-area 0/상하 inset, 200% 글자 확대에서 제목·뒤로·사냥·최종 본문 항목이 접근 가능하고 세로 스크롤이 중첩되지 않는다. 긴 이름·빈 가방·많은 장비·다수 카드 슬롯을 포함한다.
2. **선택/경로:** 영웅 B 선택→스탯→의상→카드→파티 순서 변경 후에도 B가 유지된다. 공용 탭에는 불필요한 선택 줄이 없다. 지도 상세·상점·카드 삽입 확인 취소 후 정확한 부모와 스크롤로 돌아간다. 같은 탭 재클릭, 설정 복귀, 브라우저 Back, NPC 바로가기를 확인한다.
3. **전투 관찰:** 1/3인·후열·자유 추격·맵 모서리·사망/부활·전멸에서 선택 영웅 전신과 화면 밖 표시를 영상으로 확인한다. 띠 접기/펼치기가 월드 재생성·보상 재적용·몬스터 집중 공격·NPC 실행을 일으키지 않는다. 접힘 중에도 전투·사운드·희귀 알림이 진행되고 복귀 때 과거 사건이 한꺼번에 재생되지 않는다.
4. **입력/판정:** 실제 DOM 박스로 44×44 하한과 겹침을 확인한다. 스탯 위에서 스크롤해도 포인트가 소비되지 않는다. MAX/선행 부족/포인트 부족/학습 종료/학습 가능을 구분하고, 1점이 있지만 쓸 수 없는 스탯·학습할 스킬 없는 잔여 포인트·전직 가능 조합에서 배지를 검증한다. 카드 미확인+삽입 가능 규칙도 유지한다.
5. **회귀:** 모달 확인 1회당 소비/판매/삽입 1회, 관찰 중 이동하지 않은 마을 서비스, 계속되는 저장/오프라인 반영을 확인한다. UI 선호 저장 실패·QA 분리·재접속을 확인한다. 구현 후 `npm run typecheck`, `npm run build`와 위 상호작용 검수를 수행한다. 네비게이션/배지/중복 실행에는 의미 있는 자동 검증을 붙이고 픽셀 상수만 되풀이하는 테스트는 만들지 않는다.

보스 실패·품절 경고 빈도와 극단적으로 흩어진 파티의 관찰 가독성은 아직 실측 과제다. 합의된 구조를 다시 보류할 이유는 아니지만, 각각 B 경고 조정과 A 카메라 인수 조건으로 남긴다. 이번 결과는 검토 및 구현 명세이며 코드 변경이나 실행 검증 완료 보고가 아니다.
