**판정: Phase B No-go.** 퀵슬롯과 영웅 선택 포커스의 기존 결함은 해결됐다. 사망 상태가 유지될 때의 외형 잘림도 해결됐다. 남은 차단 항목은 **부활 첫 프레임에서 이전 사망 포즈로 카메라를 맞춰 현재 외형이 잘리는 문제 한 건**이다. 지속적인 사망 외형 잘림과는 구분하며, 미실행 QA나 B 기능 미구현을 별도 차단 사유로 추가하지 않는다.

## 1. 확인 범위와 실행 결과

- `git show HEAD`와 관련 렌더러·UI·CSS·검사 코드를 검토했다.
- `npm run typecheck`: **PASS**.
- `npm run build -- --outDir /tmp/minimidgard-r6-build`: **PASS**.
- 실제 `sprite.ts`의 조립·경계 함수와 `field.ts`의 `observeCamera()`를 TypeScript 변환 후 실행했다. 브라우저 이미지 로딩/알파 측정은 저장소 PNG를 직접 디코딩한 동일한 알파 임계값의 사각형으로 대체했다. 실제 머리 픽셀은 별도로 알파 **128 이상** 좌표를 변환했다. 아래 수치는 소스·자산 기반 좌표 재현이며 브라우저 캡처가 아니다.
- 실제 `QSlot`의 이벤트 핸들러를 실행해 소비 호출 횟수와 길게 누르기를 확인했다. `HeroSelector`는 Node `EventTarget`에서 이벤트 dispatch가 끝난 뒤 예약 콜백을 실행해 네 방향 및 양 끝 순환의 포커스 호출을 확인했다. 실제 DOM 재렌더·물리 키 입력 검수와 구분한다.
- UI 자동 검사는 재실행하지 못했다. `localhost:4200` 연결 실패 후 Vite 실행이 `listen EPERM 127.0.0.1:4200`으로 종료됐다. [35/35 결과](phaseA/ui-check-result.txt)는 **제공된 실행 보고**로 인정한다.
- 저장소에서는 이 문서만 작성했다. 빌드 산출물과 재현 스크립트는 `/tmp`에 두었고, 기존 작업 트리 변경은 건드리지 않았다.

## 3. 실제 잔여 차단: 부활 첫 프레임의 포즈 불일치 — P2

근거: `src/render/field.ts:754–755`, `:766–768`, `:821`, `:976–984`.

프레임의 실행 순서는 **카메라 계산 → 영웅 그리기 → 현재 포즈 캐시 갱신 후 sprite 그리기**다. `observeCamera()`는 `lastPose`를 읽지만, 이번 프레임의 포즈는 뒤의 `drawHeroUnit()`에서 결정한다. 부활 감지가 `snapNext=true`로 만들어도, 확대율과 중심을 계산하는 경계는 여전히 누워 있는 포즈다.

### 재현

390×106 관찰 캔버스, inset 0, 선택된 novice 남성 영웅 한 명, 남성 헤어 `02`(`hair=0`), 기본 크림색(`hairColor=3`), 장비 없는 `wtype=none`, 좌표 `(500,500)`, facing `1`을 사용했다. 사망 포즈의 `t=1000`, 부활 후 idle 포즈의 `t=2000`, 카메라 dt는 16ms다.

1. 사망 포즈로 카메라를 맞춘다. 소스가 계산한 외형 y 경계는 **−54.027…0.434**, 카메라 y는 **483.987**, zoom은 **1.124621**이다. 화면 외형은 **10.249…71.497px**로 들어온다. **R5의 정지 사망 반례는 해결됐다.**
2. 영웅을 `idle`로 바꾸고, 실제 프레임 순서대로 캐시 갱신 전에 카메라를 계산한다. 부활 snap이 발생하지만 캐시가 `dead`이므로 위 카메라 값이 유지된다.
3. 이제 그릴 idle 외형의 y 상단은 **−75.510**이며 화면 상단은 **−13.911px**다. 보수적 사각형만의 문제가 아니다. `hair/male02.png`의 알파 128 이상 실제 픽셀 상단도 **−13.773px**다.
4. idle 포즈가 캐시에 들어간 **다음 프레임**에는 외형 상단이 **9.773px**로 복구된다.

즉 **첫 부활 프레임 한 장에서 약 13.8px의 머리 픽셀이 잘린다.** 지속적인 잘림이나 데이터 손실로 과장하지 않아 P2로 기록한다. 이 단독 프레이밍 조건은 한 명 파티의 전멸 후 재정비에도 해당한다. `recoverWipe()`는 같은 영웅 UID를 유지하면서 idle로 복원하므로 이전 사망 포즈 캐시가 남는다(`world.ts:1613–1642`). 재정비 위치로 이동해도 snap이 이전 외형에 맞는다는 원인은 같다.

이는 R5 §3-1에 이미 명시한 **‘선택 사망자→부활 … 8px 여백’** 완료 조건의 잔여다. 새 요구사항을 추가한 것이 아니다.

**수정 방향:** 카메라 계산 전에 이번 프레임의 포즈를 확정하고, 경계 계산과 실제 그리기가 그 동일한 포즈를 사용하게 한다. 포즈에는 `wipeUntil`, spawn→idle 변환, hurt 표현, 공격 시간, facing도 포함되어야 한다. 기존 실제 자산 경계 계산과 보간 후 clamp는 유지하면 된다.

**완료 검증:** 사망→부활 첫 프레임을 포함해 매 프레임 검사한다. 선택 변경·이동·포즈 전환도 같은 방식으로 확인한다. 선택 영웅의 현재 외형에 대해 상하좌우 8px 여백을 단언하고, 단지 다음 프레임에 복구되는 것으로 통과시키지 않는다.

## 4. 35/35의 인정 범위와 B 착수 판정

추가된 사망 검사는 60프레임을 진행한 **뒤 한 번** 경계를 검사하며, 영웅을 idle로 돌린 후에는 외형을 검사하지 않는다(`tools/ui-check.html:145–155`). 경계 조건도 `0…화면 크기`여서 8px 여백 계약보다 느슨하다. 따라서 제공된 35/35와 이번 첫 부활 프레임 실패는 모순되지 않는다.

신규 퀵슬롯 소비 횟수와 설정 버튼 실측, 선택 후 실제 activeElement 검사는 유효한 보강이다. 기존 Back·상세 부모·선행 스킬 검사도 계속 인정한다. 나머지 전체 크기/확대, 실제 Tab/Space, 필터·스크롤 복귀 등의 검수 범위는 R5에 기록된 한계로 유지하고, 이번에 별도 차단 항목으로 확대하지 않는다.

**Phase B는 No-go 유지.** §3의 포즈 시점 불일치 한 건을 수정하고 전환 첫 프레임을 재검수하면 된다. 퀵슬롯·포커스·폰트 수정을 다시 설계할 필요는 없다. 이번에는 B 착수 순서를 승인하지 않는다.
