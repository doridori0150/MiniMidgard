# Codex 3라운드 — Phase A 구현 검수

검수일: 2026-10-07 · 대상: `9808579` · 기준: [codex_r2.md §4·§5](codex_r2.md)

**판정: B 착수 No-go.** 6탭과 공통 셸의 방향은 맞고 기본 크기의 화면 구조도 상당 부분 구현됐다. 그러나 상세 복귀, 관찰 카메라, 실제 조작 크기, 스킬 상태 등 A에서 끝내기로 한 계약이 남아 있다. 알려진 지도·필터·폰트 이슈만으로 내리는 판정이 아니다.

검수 범위는 해당 커밋의 diff와 연결 코드, 제공된 스크린샷이다. 현재 HEAD에는 후속 스프라이트 변경이 있으므로 **대상 커밋을 임시 디렉터리에 추출해** 검사했다. 아래 `파일:줄`은 `9808579` 기준이다. 저장소에서는 이 문서만 작성했다.

- `npm run typecheck`: 통과.
- `npm run build`: 통과.
- 대상 모듈의 컨트롤러·카메라·배지 함수를 Node에서 실행했다. 브라우저 API는 메모리 대역으로 대체했다. 아래에서 이를 **함수 재현**으로 표시한다. DOM·화면 실측을 뜻하지 않는다.
- 연결 가능한 브라우저가 없어 새 UI 상호작용, 실제 safe-area, 200% 글자 확대, 320px, 카메라 영상 검수는 수행하지 못했다. 제공된 Claude의 상호작용 확인은 **보고된 통과**로 인정하되 범위를 확대하지 않는다.

## 2. 버그·회귀 — 우선순위와 재현

### R1 · P1 · 새 관찰 카메라가 선택 영웅 전신을 보장하지 못함

근거: `src/render/field.ts:733`의 `observeCamera`, 특히 `:747`, `:756`, `:760`.

## 3. B 전 필수 수정과 이후 개선

### B 전 필수 — 다섯 묶음

1. **복귀 상태 통합:** R2·R5·R6·R8. 상세 X/pop, 확인 취소의 부모 대상·스크롤, 후보/지도/서비스 Back, NPC history, 설정/사냥 재진입 상태를 한 계약으로 맞춘다. 가방 카드는 카드 화면 바로가기로 바꾼다.
2. **모달 격리:** R3. 배경 inert·포커스 trap/복귀, 모달의 안정된 영웅 ID, 렌더러 모달 입력 차단을 완료한다. 취소 후 대상과 확인 1회당 소비 1회를 회귀 검사한다.
3. **관찰 프레이밍:** R1. 실제 외형 경계, 즉시 유효 카메라, 사망/부활 선택 대상, 현재 화면 기준 화면 밖 수, 실제 퀵바 점유 측정을 완료한다.
4. **최소 조작성:** R4 및 §4-6·8. safe-area를 행 밖에서 한 번씩 소비하고 실제 44px 타깃·14/12/16 글자·키보드 조작을 적용한다. 작은 높이 자동 접힘과 360px 재배치를 구현한 뒤 200%/320px/긴 이름/다중 슬롯을 검사한다. 알려진 작은 필터·필수 정보 폰트도 이 묶음이다.
5. **성장 판정·검증 기반:** R7과 스킬 5상태를 완료한다. QA 첫 저장 차단·초기화 시 UI 선호 삭제를 포함하고, 명세 §5의 navigation/배지/중복 실행 자동 검증을 추가한다. 기존 빌드 통과를 이 검증의 대체로 삼지 않는다.

### 이후 개선으로 남길 수 있음

- 세계 지도 그림의 최초 접힘/펼침 버튼. 단일 스크롤은 이미 개선됐으므로 위 기능 오류보다 우선순위가 낮다. 계속 미루면 §4-5의 명시적 이월 항목으로 기록한다.
- 전직 배지 점멸 제거, 공통 셸에서 쓰지 않는 `.sheet/.hero-tabs` 및 패널 fallback 정리, 남은 옛 메뉴 안내 문구 정돈. 기능 복구와 함께 고치면 좋지만 별도의 큰 작업으로 확대하지 않는다.
- 띠의 정확한 행동 이유, 레일 정보 다이어트, 퀵바 빈 칸 접기, 스탯 구매량·추천 미리보기는 원래 B 범위다. 이유 라벨 부재 자체는 A 결함이 아니다.
- 카드 빈 화면·획득처 가림·장비 비교는 C, 세션/오프라인 보고 확장은 D에서 진행한다.

브라우저 history의 세부 구현 방식은 바꿀 수 있지만, **뒤로 한 번에 어디로 돌아오는가**라는 사용자 계약까지 보류 사항으로 흡수해서는 안 된다.

## 4. 최종 착수 판단

**No-go — A를 인수 완료로 처리하고 B를 시작하기에는 이르다.** 셸 구조를 되돌리거나 6탭 설계를 다시 토론할 필요는 없다. 위 다섯 묶음의 수정과 재검수를 먼저 끝내면 된다.

재검수의 핵심은 ① 확인 취소 후 같은 대상/위치, ② 하위 화면·NPC의 동일 Back 동작, ③ 사망/부활까지 선택 영웅 전신, ④ inset·글자 확대에서도 실제 조작 가능한 UI, ⑤ 스킬 상태/배지의 실제 행동 가능성이다. 같은 QA 상태의 390×844·360×800·500×900 전체 메뉴/내부 탭과 카메라 영상을 함께 확인해야 한다. 빌드·타입 검사 통과와 현재 정지 스크린샷만으로 이 항목들을 인수할 수는 없다.
