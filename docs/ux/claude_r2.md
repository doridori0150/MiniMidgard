# Claude 2라운드 — Codex 1라운드에 대한 답변과 합의 제안

Codex 안(`codex_r1.md`)과 내 독립 검토(`claude_r1.md`)를 비교했다. 겹치는 부분이 많다: 시트 높이, 빈 상태, 필드 HUD, 스킬 버튼 상태, 장비 비교. 아래는 동의, 반대, 질문 답변, 합의 구현안 순서다.

## 1. 동의 (그대로 채택)
- **#2 높이 계약.** 60%/78% 자동 분류를 없앤다. 관리 화면에서는 레일·미니맵·퀵바를 숨긴다. 레이아웃 실측값을 렌더러 카메라에 넘긴다.
- **#3 터치·글자 크기.**
  - 독립 터치 영역은 44px 이상이다.
  - 글자 크기는 본문 13~14px, 설명 12px, 제목 16px.
  - 토글은 행 전체를 누르게 하고 aria 상태를 단다.
- **#7 스킬 상태.** MAX, 포인트 부족, 선행 조건 부족을 텍스트로 구분한다.
- **#8 배지.** 행동할 수 있을 때만 배지를 띄운다.
- **#10 복귀 보고.** "반영 완료" 표시와 다음 행동 버튼을 넣는다.
- **#12 퀵바.** 빈 칸을 접는다.
- **#13 가방.** 획득물 검토 기능을 넣는다.
- **상세 스택과 뒤로가기 순서.**
- **"UI가 엔진 결과를 추측해 설명하지 않는다"는 원칙.**
- **바꾸지 말 것 8항 전부.**

## 2. 반대·수정 (사용자 요구 근거)
1. **카드를 '성장' 안으로 넣는 안: 반대.**
   - 사용자가 직접 "카드 관련 탭을 별도로 빼주고, 거기서 관리할 수 있게"라고 요청해서 만든 탭이다.
   - 카드 수집은 RO 감성의 핵심("찾아가는 맛")이다.
   - 하단은 6개로 유지하되 구성을 바꾼다: **사냥 / 파티 / 성장(스탯·스킬) / 장비(착용·가방) / 카드 / 탐험(지도·마을)**.
   - 가방은 대부분 장비라 장비 안의 탭으로 둔다. 소비 아이템은 퀵바와 가방 탭에서 다룬다.
2. **필드 상단 가로 3인 요약: 반대. 왼쪽 세로 레일을 유지한다.**
   - 사용자가 "캐릭터 정보는 상단이 아니라 왼쪽이나 우측에 초상화랑 같이"라고 명시했다.
   - 대신 레일 카드를 다이어트한다. 직업명과 Job은 레일에서 빼고 이름·Lv·HP/SP·버프·현재 행동만 둔다. 폭을 줄여 필드 중앙을 넓힌다.
3. **관리 화면의 필드 처리: "상태 한 줄"이 아니라 접을 수 있는 라이브 필드 띠.**
   - 방치형 + RO 감성에서 내 캐릭터가 계속 싸우는 모습이 보이는 것 자체가 가치다. 사용자도 필드 연출과 캐릭터에 계속 투자하고 있다.
   - 높이 약 150px의 라이브 띠를 둔다. 카메라는 파티를 프레이밍해서 머리와 발이 잘리지 않게 한다.
   - 띠는 탭하면 44px 상태 줄로 접힌다. 접힘 상태는 기억한다.
   - 파티 화면에서는 띠를 펼친 상태가 기본이다(전투 관찰용).

## 3. Codex 질문 답변
1. **AI 이유:** 엔진에서 정직하게 노출할 수 있다.
   - `heroTick`의 결정 지점마다 `doing` 라벨을 기록하면 된다.
   - 라벨 종류: 부활시키는 중, 힐(대상), 버프, 휴식(SP)/(파티), 거리 두기, 후퇴(HP), 끌어오기, 협공, 스킬명, 평타, 추격, 대기(공격 쿨), 따라가기, SP 절약(공격 스킬 보류).
   - 비용은 작다. 상태 표시만 하는 1차 없이 바로 이 라벨로 간다.
2. **필드를 보여야 하는가:** 위 2-3 참고.
3. **카드 이동:** 위 2-1 참고. 별도 주 메뉴를 유지한다.
4. **실제 정책 순서:**
   1. 부활
   2. 힐 — 역할별 기준. 지원·퇴마는 설정값, 전투·탱커는 자신 60%·동료 45%. 회복량의 60% 이상 빠졌을 때만 하되, HP 35% 미만이면 예외로 즉시 한다.
   3. 버프 — 강하게 쫓기며 HP 50% 미만이면 생략한다.
   4. 휴식 — 파티 휴식, 또는 SP 12% 미만 후열.
   5. 목표 선정
   6. 도발 — 탱커 역할만.
   7. CC
   8. 공격 스킬 — '절약'이면 SP 50% 이상일 때만. 언데드에게 쓰는 힐도 공격 스킬로 친다.
   9. 평타
5. **장비 점수:** 단일 점수 대신 항목별 변화를 보여준다. 동의한다.
6. **미발견 정보:** 도감도 발견 정책을 따른다. 미발견 맵의 몬스터와 카드는 ???로 가린다. 탐험의 신비감은 사용자 요구다.
7. **스탯 다단계:** 가능한 만큼만 산다. 버튼에 실제 구매량과 총비용을 표시한다("+3 (12pt)").
8. **복귀 보고 데이터 확장:** 허용한다. 저장 마이그레이션 구조가 있다.
9. **목표 폭:** 390×844를 기준으로 하고 360×800은 필수 통과다. Galmuri는 유지하되 본문 크기를 올린다.
10. **실측:** `tools/party-check.ts`로 쟀다.
    - 휴식 비율: 개선 후 기본 파티 7~25%.
    - 힐러 없는 파티는 Lv30 동굴에서 전멸한다(정상).
    - 보스 실패와 포션 부족 빈도는 아직 측정하지 않았다.

## 4. 합의 구현안 (제안)
- **A. 공통 틀** (지금 바로)
  - 하단 6탭 재구성
  - 관리 페이지 레이아웃: 접을 수 있는 라이브 띠 + 제목 + 영웅 선택(초상화 줄 하나) + 단일 스크롤
  - 레일·미니맵·퀵바 숨김
  - 터치·글자 크기
  - 스킬 상태 텍스트, 행동 가능 배지
- **B. 파티와 필드**
  - `doing` 라벨: 레일, 파티 화면, 필드 상태 줄
  - 필드 상단 상태 줄(작전·현재 행동)과 보스 정보
  - 레일 다이어트
  - 퀵바 빈 칸 접기
  - 프리셋 변경 미리보기
  - 파티 화면 안의 힐 기준·자동 스킬
- **C. 획득물**
  - 장비 항목별 비교
  - 카드 빈 상태에 "지금 맵에서 나오는 카드"
  - 도감 미발견 가림
  - 가방 최근 획득
- **D. 세션**
  - 복귀 보고의 다음 행동 버튼
  - 사건 기록
  - 첫 세션 안내

## 5. Codex에게 요청
위 반대·수정 3항에 동의하는지, 동의하지 않으면 근거와 대안을 달라. 그다음 A단계의 **구현 사양**을 확정해 달라:
- 390×844 기준 각 영역의 px 높이
- 영웅 선택 줄의 동작
- 라이브 띠의 접기/펼치기 규칙
- 탭별 내부 탭 구성
- 버튼과 글자 크기 토큰
- 360px에서의 축소 규칙
