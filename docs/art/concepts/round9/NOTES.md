# Round 9 — 2등신 도트 쿠키

## 제작 전 레퍼런스 해석

이 문단은 이미지 생성 전에 작성했다. 목표는 큰 머리와 짧은 몸에 얼굴·머리·복식의 특징을 응축하면서, 작은 화면에서도 색 덩어리가 서로 뭉개지지 않는 도트 캐릭터다. 머리카락은 가느다란 선을 흩뿌리는 대신 두세 개의 굵은 머리 다발과 이어지는 밝은 띠로 부피를 만든다. 눈은 작은 어두운 덩어리와 밝은 한 점으로 표정을 주고, 피부와 머리의 경계를 따뜻한 색으로 정리한다. 갑옷의 단단한 반사와 천의 넓은 중간색 면을 구별하며, 붉은 허리띠와 갈색 부츠가 축소 상태에서도 남도록 한다. 외곽선은 전부 검게 두르는 대신 머리에는 갈색, 옷과 금속에는 짙은 청회색을 사용한다.

브리프에서 지정한 ‘도깨비의세계’는 이러한 작은 캐릭터의 외형 완성도와 배경 위 판독성의 기준으로 해석한다. 공식 소개는 2D 도트 캐릭터와 3D 배경을 결합한 2.5D 비주얼 및 캐릭터 꾸미기를 명시한다. 다만 이 환경에서 공식 이미지 원본의 시각 열람과 쇼케이스 영상 재생은 확보하지 못했다. 위의 세부 도트 설계는 공식 원화의 픽셀을 직접 분석했다는 주장이 아니라, 사용자 브리프를 제작 가능한 기준으로 풀어 쓴 해석이다. 해당 작품의 캐릭터·의상·이미지를 복제하거나 저장하지 않는다.

- 공식 설명: https://game.kakao.com/ar/YaMnV9/atb_K-GAM02M0127/0f03a8c6-f778-47e5-bdc3-ddf3c7d1c5dd
- 제작사 소개: https://www.supercat.co.kr/supercat-games
- 우리 의상 기준: `../../concepts/round6/r6_lineup.png`의 화면 왼쪽 검사. 밝은 머리, 은색 흉갑, 파란 튜닉, 붉은 허리띠, 갈색 가죽 장비, 흰 바지, 한손검을 유지한다.
- 개선 기준: `../../../art-production/pixel-hero-r8/verification/review_p2.png`. 2등신과 작은 화면의 명료함은 이어받되, 기하학적인 머리·몸통, 빈약한 머릿결 덩어리와 재질 표현을 개선한다.

## 세 후보의 설계

- A: 둥근 얼굴과 부드러운 옆가르마. 볼륨 있는 둥근 단발, 균형 잡힌 은색 흉갑과 청색 튜닉. 따뜻한 피부와 중성 크림 머리.
- B: 또렷하고 자신 있는 눈매, 바깥으로 뻗는 층진 단발. 은색 갑옷 비중을 높이고 더 차가운 청색과 선명한 붉은색으로 대비.
- C: 부드러운 눈과 작은 미소, 가운데가 살짝 갈라진 물결 단발. 작은 흉갑과 얇은 어깨 갑옷으로 파란 천 면적을 넓히고 차분한 색면으로 구별.

## 제작 원칙

내장 이미지 생성 도구가 캐릭터와 검격 이펙트를 그린다. 이후 코드는 셀 샘플링, 팔레트 제한, 알파 이진화, 확대와 비교판 조립만 수행한다. 사람이 시각적으로 검수하듯 각 결과를 확인하고 좌표별 픽셀 수정 내역을 남긴다. 다각형·선으로 신체나 장비를 생성하지 않는다. 최종 대기 높이는 46–50px, 약 2–2.3등신, 오른쪽 3/4 시점이다. 동작은 후보 외형을 판단하는 한 장의 키 포즈이며 애니메이션 완성본이 아니다.

## 납품 파일과 실제 결과

`r9_compare.png`에서 A/B/C의 대기와 검격을 각각 6×, 2×로 나란히 비교할 수 있다. 아래에는 실제 1×도 넣었다. `r9a_field.png`, `r9b_field.png`, `r9c_field.png`는 같은 잔디와 같은 작은 슬라임 옆에서 대기·검격을 1×/2×로 보여 준다. 이미지 뷰어를 100%로 설정해야 표시된 배율과 실제 화면 픽셀이 일치한다.

| 후보 | 얼굴·머리 | 복식과 색 처리 | 대기 / 검격 불투명 색 수 |
| --- | --- | --- | --- |
| A | 둥근 볼, 옆으로 흐르는 앞머리, 안으로 말린 큰 머리 다발 | 중간 비중의 흉갑, 크림 머리와 선명한 청색·붉은색 | 29 / 29 |
| B | 눈썹으로 강조한 자신 있는 표정, 바깥으로 뻗친 층진 머리 | 밝은 흉갑과 은색 어깨판 비중이 가장 큼, 회백색 머리·코발트·진홍 | 28 / 29 |
| C | 부드러운 얼굴, 이마를 드러낸 물결 단발 | 작은 흉갑, 넓은 청색 천, 차분한 청회색·말린 장미색 | 28 / 29 |

세 대기 스프라이트 모두 불투명 세로 범위가 정확히 **48px**다. 캔버스는 대기 64×64, 검격 96×80이며, 각각 동일한 이름의 `_6x.png`를 제공한다. 모든 픽셀의 알파는 **0 또는 255**이고, 투명색을 포함해도 각 이미지가 **30색 이하**다. 전체 재질 팔레트는 후보당 31개의 불투명 색으로 고정했다. 배경 비교 이미지에는 이 팔레트 제한을 적용하지 않는다.

## 생성 → 격자 정리 → 수동 검수

1. `NOTES.md`의 첫 레퍼런스 해석을 먼저 작성한 후 내장 `image_gen.imagegen`을 사용했다. 사용한 프롬프트 원문 전부는 `PROMPTS.json`에 있다. A의 최초 생성은 세부가 지나치게 촘촘하여 채택하지 않았고, 큰 머리와 굵은 픽셀 덩어리로 재생성한 결과를 사용했다. 최초본도 `sources/r9a_initial.png`로 남겼다.
2. 각 후보는 대기·검격을 한 장에 그린 생성 원본에서 추출했다. 생성 원본의 픽셀 간격은 완전한 정수 격자가 아니므로, 대기 높이를 48개의 정사각 셀로 정규화하고 **각 셀 중심의 색 하나만** 채택했다. 대기와 검격에 같은 후보별 셀 간격을 사용했다. 보간·흐린 축소·디더링을 하지 않았다. 사용한 원본 경계와 셀 간격은 `verification/manifest.json`에 기록했다.
3. 원본 알파 200 이상을 255로, 나머지를 0으로 정리해 생성본의 반투명 가장자리와 빛 번짐을 제거했다. 샘플 색은 명시적인 재질 팔레트에 대응시켰다. 머리·천·피부·금속의 명암은 원본이 그린 덩어리를 유지했다.
4. 여섯 스프라이트의 확대판과 좌표 격자를 직접 보며 수정할 머리 영역을 선택했다. A의 복숭아색 머리 오염, B/C의 끊긴 외곽색과 잡색을 정리했다. 선택한 영역의 일괄 색 대응과 기존 불투명 윤곽 픽셀 정리는 보조 코드로 적용했고, 눈 중심·캐치라이트·금속 반사점·고립 픽셀은 좌표를 지정해 수정했다. 이는 별도의 인간 화가가 작업했다는 의미가 아니다. 실제 변경 좌표와 사유는 `pixel_edits.json`, 선택 영역은 `verification/hair_selection_spans.json`에 남겼다.
5. C에서 칼끝을 지나 뒤로 돌아오던 검격 꼬리를 지우고, 재검수에서 발견한 마지막 은백색 고립 픽셀도 제거했다. 두 발과 검을 연결하는 신체 포즈와 초승달 본체는 생성 원본에서 가져왔으며, 코드로 신체 다각형·장비·검격 곡선을 그리지 않았다.
6. 슬라임 역시 별도 이미지 생성 원본을 셀 샘플링한 `slime.png`다. 잔디는 프로젝트에 이미 있던 `src/assets/kits/meadow/grass.jpg`를 복사해 비교용 배경으로만 사용했다. 제3자 게임 이미지는 저장하지 않았다.

## 최종 검수

- 여섯 스프라이트를 6× 비교판으로 직접 확인했다. 얼굴 방향, 머리 덩어리, 눈의 밝은 점, 은색 갑옷, 붉은 허리띠, 흰 바지, 갈색 부츠와 한손검이 유지된다.
- 세 필드 이미지를 1×/2×로 확인했다. 머리와 잔디 사이의 어두운 외곽색이 남고, 허리띠와 부츠가 작은 화면에서 구분된다.
- 검격은 몸 앞쪽의 굵은 밝은 호, 전방으로 내민 팔과 칼끝, 벌어진 다리로 읽힌다. 연속 동작의 자연스러움이나 타격 타이밍까지 검증한 애니메이션은 아니다.
- `verify.py` 검사 통과: 요청한 파일 18개 존재, 모든 대기 높이 48px, 색 수 제한, 알파 이진화, 6× 최근접 확대의 픽셀 일치, 캔버스 잘림 없음, 여섯 이미지 모두 8방향 연결 기준 하나의 연결 성분으로 고립 픽셀 없음. 결과와 SHA256은 `verification/VALIDATION.json`에 있다.
- 외형 선택 의견: A는 기존 쿠키의 부드러운 인상을 가장 잘 잇고, B는 작은 크기에서 검사 역할과 표정이 가장 강하며, C는 천과 머리의 부드러운 인상을 강조한다. 상용 레퍼런스와의 동일 품질을 객관적으로 인증한 것은 아니다.

## 재현과 범위

Python 3와 Pillow로 `python assemble.py` 실행 시 보존한 생성 원본과 픽셀 수정 목록에서 결과물을 다시 조립한다. `python verify.py`로 납품 조건을 확인한다. `author_cleanup.py`는 시각 검수로 지정한 영역·좌표를 수정 목록으로 펼치는 기록용 보조 도구다. `verification/*_grid.png`와 `*_before.png`는 수정 전 검사 자료다.

프로젝트 파일 쓰기는 `docs/art/concepts/round9/` 안에서만 수행했다. 게임 실행 코드와 기존 아트는 변경하지 않았으며, 커밋·푸시는 하지 않았다. 이번 결과는 외형 선택용 콘셉트이고 게임 런타임에는 통합하지 않았다.
