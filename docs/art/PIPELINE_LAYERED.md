# 층 조립 영웅 파이프라인 (2026-10-11)

어새신 96px 시범의 실패 원인을 고치고, 도깨비의세계 방식을 따르는 새 영웅 그림 파이프라인입니다. 이 문서가 ① 규격서입니다.
- 기계 판독용 규격: `docs/art-production/hero-layered/spec.json`
- 레퍼런스(로컬 전용): `reference/`(README 참고)

## 0. 사용자 결정 (원문)
- 크기: "96. 같은 키. 선명해야 뭐가 보이지"
  - 96px로 그리되 화면 키는 지금 영웅과 같습니다(필드 59px, 폰 약 70px).
- 순서: "다시 캐릭터부터 가자. 또 실수하지말고. 일단 크기 - 컨셉 - 공격 모션"
- 그림체와 구조:
  - "이 스타일로 한 번 해보자. 도깨비의 세계란 게임이고. 보니까 몸통/얼굴/ 겉 의상을 따로 만들어서 합체 하는 형식으로 제작했네. 일단 작업 파이프 라인을 설계 후 진행하는 걸로."
  - "얼굴도 보니까 레고 머리처럼 되어 있어."
  - "저 게임은 8방향이긴 한데 우린 일단 2방향 (좌/ 우)"
  - "스프라이트는 기본 4장으로 동작이 크게 변경되는 부분을 기준으로."
  - "무기와 이펙트는 레이어 추가하는 형태로."
  - "동작도 크게 몇 가지로 나눈 후 이펙트로 처리를 했고, 투사체나 특수한 모션이 필요한 건 공용 이펙트로 만들어서 순간 캐릭터가 사라지게 만들었네. 이런 파이프 라인도 필요해"
- 그림 규칙 세 가지(이전 결정, 그대로 유지):
  1. 등신대, 컨셉 스타일, 전반적인 크기 영역을 맞출 것
  2. 레퍼런스를 체크할 것
  3. 스프라이트 애니메이션을 사전에 어떤 동작을 할지 고려하여, 1장씩 생성하고, 연결할 것

## 1. 지난번 실패와 이번의 막는 장치
| 실패 원인 | 막는 장치 |
|---|---|
| 장마다 새로 생성해서 다리, 손, 발이 매번 새로 그려졌다 | 동작은 맨몸에만 둔다. 새 장은 앞 장을 고쳐서 만들고, 바꿀 영역 밖의 변경 픽셀은 0이어야 한다(검사) |
| 모션 기준이 없었다. SSOT는 생김새만 정했다 | ③ 모션 기준표(라그나로크 분해에서 4장 선택)를 사용자가 승인하기 전에는 그리지 않는다. 요청서 수치는 이 표에서만 가져온다 |
| 검수가 숫자만 봤다 | 숫자 검사는 거르는 용도다. 판정은 폰 화면, 게임 크기에서 눈으로 한다 |
| 잔상이 몸 그림을 지웠다 | 잔상과 휘두름은 이펙트 층에만 둔다. 몸 층에 그리지 않는다 |
| 세 세션이 따로 확인을 요청했다 | 확인은 한 곳에서, 그림 한 장이나 재생 하나로 받는다 |

## 2. 층 구조 (뒤 → 앞)
`weapon(뒤)` → `head_back` → `body` → `outfit` → `head` → `near_arm` → `outfit_arm` → `weapon(앞)` → `grip` → 이펙트

- **body (맨몸):** 피부와 몸에 붙는 기본 내의, 다리, 몸통, 먼 팔, 목을 그립니다. 동작은 이 층에만 있습니다. 같은 성별·체형의 모든 직업이 같이 씁니다.
- **near_arm (가까운 팔):** 따로 둡니다. 무기를 쥔 팔이 옷 앞을 지나가기 때문입니다(스타듀밸리 방식). 장마다 `nearArmZ`를 front 또는 behind로 정합니다. 팔을 몸 뒤로 젖히는 장은 behind입니다.
- **outfit / outfit_arm (겉옷):** 직업마다, 장마다 그 몸에 맞춰 입힙니다. 동작을 바꾸지 않습니다. 몸이 삐져나오는 자리는 겉옷이 덮습니다.
- **head (레고 머리):** 얼굴, 머리카락, 마스크를 한 덩어리로 그립니다. 각도는 몇 장만 둡니다(`front`, `down`, `hurt`). 장마다 `head.point`(목 위 붙는 점)와 `head.frame`만 정합니다. 목은 body에 있고, 머리 아래 2px가 목 위를 덮습니다.
- **head_back:** 몸 뒤로 넘어가는 머리카락이나 천이 있을 때만 둡니다.
- **weapon / grip:** 무기 종류마다, 장마다 둡니다. `grip`(쥔 점), `angle`, `z`(front/behind)를 정합니다. 스킬 중에는 숨기거나 이펙트 무기로 바꿀 수 있습니다.
- **이펙트:** 게임 이펙트 라이브러리를 씁니다(`src/assets/fx`, 기본 14종 + 조립). 그림 파일에는 넣지 않습니다.

## 3. 규격 (①)
- **캔버스** 256×240, 발 기준점 (128,224), 발 맨 아랫줄 y 223. 모든 층과 모든 장이 같은 캔버스와 같은 기준점을 씁니다(갈아 끼우기 조건).
- **키** 96px(정수리~발). 게임 화면 키는 bodyPx 59(지금 영웅과 같음).
- **비율** 머리(정수리~턱)가 키의 약 40%, 곧 약 38px입니다(약 2.5등신). 머리카락을 포함한 머리 폭은 50px 이하입니다.
  - 도깨비의세계 화면에서 잰 값: 머리 약 40%.
  - 승인했던 96px 대기 B는 머리가 47px로 49%였습니다(2등신). 이번에는 레퍼런스 비율을 따르고, ② 단계에서 사용자가 판정합니다.
- **시점** 오른쪽 3/4 한 방향만 그립니다. 왼쪽은 엔진이 좌우를 뒤집습니다.
- **그림체** 도트입니다.
  - 바깥 외곽선은 1px 어두운색, 안쪽 선은 그 재질의 어두운 단입니다.
  - 재질마다 명암 3단과 하이라이트 1단을 씁니다. 빛은 왼쪽 위에서 옵니다.
  - 디더링, 흐림, 반투명 가장자리를 쓰지 않습니다. 알파는 0 또는 255입니다.
- **머리색** 머리카락은 키색 4단으로 그리고, 게임이 팔레트를 바꿉니다(기존 hairKeys 방식).
- **파일** 장 폴더마다 층별 PNG, `composite.png`, `composite_4x.png`, `pose.json`을 둡니다. 형식은 `spec.json`을 따릅니다.

## 4. 기본 동작 (몸 체형마다 한 벌, 동작마다 크게 바뀌는 자세 4장)
| 동작 | 장 | 역할 | 쓰는 곳 |
|---|---|---|---|
| idle | 4 | 기본 · 들숨 · 기본 · 날숨 | 전 직업 |
| walk | 4 | 오른발 접지 · 통과 · 왼발 접지 · 통과 | 전 직업 |
| attack_slash | 4 | 준비 · 정점 · 접촉 · 회수 | 검, 도끼, 둔기, 지팡이 |
| attack_thrust | 4 | 당김 · 정점 · 접촉(가장 뻗음) · 회수 | 창, 단검, 카타르, 주먹 |
| attack_shoot | 4 | 들기 · 당김 · 놓음 · 회수 | 활 |
| cast | 4 | 모으기 시작 · 모으기 · 방출 · 회수 | 마법, 버프, 힐 |
| hurt | 2 | 움찔 · 복귀 | 전 직업 |
| dead | 4 | 휘청 · 무릎 · 쓰러짐 · 누움 | 전 직업 |
| sit | 1 | 앉음 | 휴식 |

- 몸 체형 하나에 31장, 남녀 두 체형이면 62장입니다.
- 장별 시간, 정수리 높이, 디딘 발과 손 위치는 ③ 모션 기준표에서 정합니다. 라그나로크 분해 `docs/art/motion-templates/*.json`에서 4장을 고르고, 승인받은 뒤 그립니다.
- **유지 자세:** 스킬은 attack의 정점이나 접촉 장, cast의 모으기 장을 붙잡아 쓰고, 새로 그리지 않습니다.

## 5. 스킬 = 기본 동작 + 이펙트 (스킬 전용 동작은 그리지 않음)
도깨비의세계 스킬 영상(`reference/dokkaebi-style/skills-video/`)에서 확인한 방식입니다.

| 방식 | 내용 | 예 |
|---|---|---|
| 동작 + 이펙트 조립 | 기본 동작 4장이나 유지 자세 위에 이펙트를 조립 | 강타, 베기류 |
| 무기 숨김·교체 | 스킬 동안 무기 층을 숨기거나 이펙트 무기로 교체 | 얼음 창, 빛나는 칼, 불주먹 |
| 공용 투사체 | 투사체 하나를 원소 색만 바꾸고 반복 | 화살, 마법탄, 투척, 주먹 연사 |
| 분신(잔상) | 캐릭터를 숨기고, 엔진이 캐릭터의 기존 자세 그림을 원소 색으로 칠해 분신으로 띄움. 끝나면 제자리나 새 자리에 다시 나타남 | 돌진, 연타(음속 연격), 순간이동, 궁극기 |
| 공용 연출 | 돌진 잔상, 연타 잔상, 회오리, 순간이동 연기, 도약 낙하 | 직업 공용 |
| 대상 반응 | 띄우기, 밀기, 흔들기를 엔진이 대상 위치로 처리 | 띄우기 베기 |
| 바닥 잔여 | 먹물, 그을음, 얼음 자국 | 큰 기술 뒤 |
| 회전 | 2방향이라 좌우 뒤집기를 빠르게 반복하고 회전 고리 이펙트를 얹음 | 회전 강타 |

- 지금 게임의 스킬 전용 동작 53개는 이 방식으로 대체합니다.
- **엔진에 필요한 것(필드 코드, 적용할 때 사용자 승인):**
  - 렌더러의 겉옷, 레고 머리, 가까운 팔 층
  - 타임라인의 캐릭터 숨김, 다시 나타날 위치, 무기 숨김·교체, 분신(장 번호, 색, 위치), 대상 반응 트랙

## 6. 겉옷 물량 줄이기 (② 컨셉 단계에서 정함)
- 직업마다 기본 동작 31장에 겉옷을 입히면 12직업에 약 370장입니다.
- 줄이는 방법 후보:
  - 기본 옷 몇 벌(튜닉, 로브, 갑옷, 경장)에 직업별로 색만 바꿉니다(스타듀밸리 셔츠 방식).
  - 2차 직업은 1차 옷에 장식만 더합니다.

## 7. 단계와 확인 지점
| 단계 | 하는 일 | 사용자 확인 | 생성 예상 |
|---|---|---|---|
| ① 규격 | 이 문서와 `spec.json` | 승인함(2026-10-11 "그래 그리고 이어서 진행해봐") | 0 |
| ② 컨셉 | 남자 맨몸 대기 1장 → 어새신 레고 머리(front) → 어새신 겉옷 → 합친 대기 | 합친 대기 1장, 폰 화면 게임 크기 | 3~6 |
| ③ 모션 기준표 | 공격(찌르기, 카타르) 4장의 실루엣, 시간, 발과 손 위치 | 표 1장 | 0~1 |
| ④ 맨몸 공격 | 4장을 앞 장 고치기로 만들고 무대에서 재생 | 옷 없는 몸 동작, 게임 크기 | 4~8 |
| ⑤ 옷 입히기 | 겉옷, 머리, 팔, 무기를 장마다 맞춤 | 완성 동작, 게임 크기 | 4~8 |
| ⑥ 게임 적용 | 렌더러와 타임라인에 층과 트랙 추가 | 적용 승인 | 0 |

- 생성 수가 예상을 넘으면 더 돌리기 전에 사용자에게 먼저 말합니다.
- 공수는 `docs/art-production/hero-layered/LOG.md`에 적습니다.
