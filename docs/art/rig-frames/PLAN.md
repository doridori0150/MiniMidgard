# 프레임 애니메이션 파일럿 — 제작 방식과 재생 계약

초보자·검사의 몸을 **자세별 완성 PNG**로 교체하고, 얼굴·헤어·머리장식은 하나의 머리 유닛으로 합성해서 목에 붙인다. 팔·다리 관절 회전이나 접촉 순간 팔 교체는 없다. 기존 게임 소스는 수정하지 않았다. 이 폴더가 이식용 독립 패키지다.

## 원화와 제작

- 내장 `image_gen.imagegen`으로 승인 라인업을 참조한 초보자 몸 시트를 만들고, 그 시트를 편집해 동일 포즈의 검사 의상을 만들었다. 대머리 표정 시트도 생성했다. 원본과 실제 프롬프트는 `source/*_sheet.png`, `source/prompts.json`에 보존했다.
- `idle_0` 몸은 생성본 대신 **승인 라인업에서 직접 분리**했다. 승인 자세의 팔 길이, 굽힘, 허리, 발 간격을 유지한다.
- `idle_1`은 그 몸의 세로 길이를 약 1.3% 늘려 구운 호흡 프레임이다. 발 위치는 고정한다. 새로 생성한 idle을 사용하면 어깨·팔 자세가 달라졌기 때문에 이 부분은 별도 재작화보다 원화 보존을 우선했다. 런타임 보간은 없다.
- 나머지 12장은 팔·몸통·양 다리가 함께 그려진 포즈다. 걷기의 무릎 굽힘, 지지발 교대, 공격의 몸 기울기, 앉기와 옆으로 누운 자세를 그림 자체에 담았다.
- 헤어 01은 라인업 초보자, 02는 승인 헤어 시트 여성형에서 추출했다. 일반 표정의 눈·눈썹·입도 승인 초보자에서 추출했다. 생성한 대머리 원화는 가려지는 두상과 공용 얼굴 윤곽에 쓰고, 표정 잉크는 별도 PNG로 분리했다.
- 기본 얼굴 하나를 normal / hurt / ko에 공유한다. 표정이 바뀌어도 두상·헤어·앵커는 바뀌지 않는다. 머리는 프레임마다 생성하지 않는다.
- 단검·검·새싹·별 핀은 기존 독립 장비 PNG를 복사·정규화했다. 기존 컷아웃의 몸 부품은 쓰지 않는다.
- 출력 파일 크기를 먼저 정규화하고 마스크를 적용한다. 몸 동작 프레임은 고정 팔레트로 평탄화한다. 원화 idle은 원본의 색 변화를 보존했다. 원화의 모든 색을 바꾸면 원화 일치가 떨어지기 때문이다.
- `source/hand_measurements.json`은 주먹 피부 영역의 실측 중심이다. `source/body_measurements.json`은 초기 분리 프레임의 알파 경계다. 이를 이용해 손과 지면을 정규화한다. 프롬프트의 숫자 좌표를 믿지 않는다.

## 캔버스·원점

- 스키마: `minimidgard.frames/1`.
- 조립 캔버스: **1024 × 800**. 좌상단 (0,0), x 오른쪽, y 아래쪽. 각도는 도 단위이며 양수가 시계 방향이다.
- 원점: **(400, 725)**, `manifest.canvas.origin`. 서 있는 기본 자세의 두 발 사이 지면이다. PNG는 캔버스 전체 크기가 아니라 부위의 로컬 사각형이다. 몸은 `bodyPosition`에 그대로 그린다.
- 기준 캐릭터 높이 620 원화 px → 표시 높이 80 px. 화면 배율은 `80 / 620`. 게임의 76 field-unit 캐릭터에는 `76 / 620`을 쓴다. 장식과 무기가 이 높이를 넘는 것은 정상이며, 모든 프레임을 각각 바운딩 박스에 맞춰 리사이즈하면 안 된다.
- 좌우 반전은 모든 장비를 합성한 뒤 원점 x를 중심으로 한 번 적용한다. 왼쪽을 볼 때 공격 칼끝도 왼쪽을 향한다.
- 발바닥 정렬은 동작 몸 PNG의 측정된 하단을 기준으로 한다. 누운 상태는 그린 몸과 기울인 머리의 바닥 접촉으로 판단한다. 지면에서의 작은 안티앨리어싱 차이는 검증 보고서에 수치로 남긴다.

## 프레임·타이밍

각 직업 14장, 총 28장이다. 모든 구간은 시작 포함·끝 제외다.

| 상태 | 프레임 | 구간 / 동작 |
|---|---:|---|
| idle | 2 | 800 + 800 ms, 1600 ms 느린 호흡 루프 |
| walk | 4 | 각 180 ms, 720 ms 루프 |
| attack | 3 | 준비 0–100 / 접촉 100–180 / 마무리 180–280 ms |
| cast | 2 | 각 360 ms, 720 ms 채널링 루프 |
| sit | 1 | 유지 |
| hurt | 1 | hurt 표정으로 유지 |
| dead | 1 | 옆으로 누운 몸 + ko 표정으로 유지 |

- 공격 전체는 **280 ms**, 게임의 hit 이벤트는 **140 ms**다. 140 ms에 `attack_1`이 선택되고, 칼의 grip→tip 방향은 오른쪽 수평 0°다. 이벤트 실행은 게임 시뮬레이션의 책임이며 플레이어가 별도로 피해를 발생시키지 않는다.
- 105 field units/s × 0.72 s = 한 걷기 주기당 75.6 units. 키 76 units에서 주기당 약 한 키를 이동한다. 이동량은 게임이 처리한다. 프레임은 제자리에서 재생한다.
- 비루프 상태는 마지막 프레임을 유지한다. attack 종료 시 idle로 전환하는 것도 게임의 책임이다. GIF만 감상을 위해 공격 후 520 ms idle을 넣는다.
- sit/hurt/dead의 manifest duration 1은 단일 프레임 선택을 위한 값이다. 상태의 실제 유지시간은 게임이 결정한다.
- 모든 프레임은 step 교체한다. 추가 tween은 없다.

## 머리·얼굴·헤어·장식

1. 헤어 뒤 → 공용 head_base → 표정 → 헤어 앞 → 머리장식 순서로 머리 로컬 공간에 합성한다.
2. 공용 로컬 목 `head.neck`을 해당 몸 프레임의 `neck.point`에 맞춘다. 머리 전체에만 `neck.angle`을 적용한다. 표정·헤어·장비 조합별 합성을 캐시해도 결과는 같다.
3. 각 헤어의 `position`은 공용 두상에 맞춘 고정 오프셋이다. 몸 프레임과 무관하다.
4. 크림 헤어에만 multiply 색을 적용한다. RGB 중 R > 127인 픽셀만 색을 곱하고, 어두운 외곽선과 알파는 보존한다. 지원 색은 cream/blue/brown/black이다.
5. 새싹은 **두상 crown**, 별 핀은 **두상 brow**에 붙는다. `head.skullAnchors`에 crown/brow/eyes/mouth가 있으며, 헤어에는 장비 앵커가 없다. 장식 위치 = 두상 앵커 + offset − 장식 pivot이다.
6. 머리장식 두 개를 동시에 착용할 수 있다. 짧은 헤어는 귀·턱·짧은 목 연결부가 더 드러난다. 얼굴 베이스는 동일하다.

## 손·무기·z 순서

- 몸 프레임의 `hand.point`는 캔버스 좌표의 주먹 중심, `hand.angle`은 무기의 절대 각도다.
- 무기는 로컬 grip을 hand.point에 맞춘 후 grip을 중심으로 회전한다. 단검과 검은 각각 PNG 한 장만 사용한다. 칼끝 tip은 grip과 같은 y에 있다.
- 기본 순서: 뒤 무기 → 몸 → 머리 유닛 → 앞 무기 → 주먹 덮개.
- `weaponZ=behind`이면 몸에 그려진 주먹이 손잡이를 가린다. 공격의 `front`에서는 무기를 그린 뒤 해당 포즈의 실제 주먹 픽셀을 `gripOverlay`로 한 번 덮는다. 이 덮개는 회전하거나 움직이는 팔 부품이 아니다.
- cast/sit/dead는 무기를 숨긴다. 장착 상태는 유지되므로 다음 무기 표시 상태에 그대로 나타난다.
- `weapon=null`, `headgear=[]`는 정상적인 빈 장비다. 알 수 없는 id는 오류다.

## 이식 기준과 재현

`player.py`의 `select_frame`, `matrix`, `multiply`, `assembly`가 기준 구현이다. 결과는 순서가 정해진 `{file, matrix, tint?}` 배열이다. 행렬은 Canvas 2D와 같은 `[a,b,c,d,tx,ty]` 규약이다. 파일마다 독립적으로 배율을 재계산하지 않는다.

```sh
cd docs/art/rig-frames
swiftc -module-cache-path .swift-cache raster.swift -o .raster
python3 build.py
python3 verify.py
python3 player.py --class swordsman --state attack --time 140 --hair 02 --gear leaf hairpin --out verification/contact.png
python3 player.py --state dead --json
```

Python은 표준 라이브러리만 사용한다. PNG/GIF 인코딩과 래스터 검증은 macOS 기본 AppKit/CoreGraphics/ImageIO를 쓰는 `raster.swift`가 맡는다. 모델 호출 없이 저장된 원본으로 재빌드된다. 이식할 게임은 Swift에 의존하지 않는다. manifest와 행렬 조립만 옮기면 된다.

## 확장 비용

- 몸: 13 직업 × 14 프레임 = **182 PNG**. 헤어·얼굴 조합만큼 몸을 다시 그리지 않는다.
- 헤어: 8종 × front/back = **16 PNG**. 크림 원본을 색상 변경한다.
- 얼굴형: 2종 각각 head_base와 normal/hurt/ko 3표정. 두상별 공용 neck과 skull anchor를 동일 계약으로 맞춘다. 이번 파일럿은 여성형 한 종류만 제공한다.
- 장비는 아이템당 한 PNG와 앵커 데이터가 기본이다. 양손 무기, 활, 긴 망토, 얼굴을 가리는 투구는 이 파일럿 범위 밖이며 추가 z/가림 규칙이 필요하다. 현재 단검/검 계약이 모든 장비에 그대로 맞는다고 가정하지 않는다.

## 납품과 검증 범위

- `assets/`: 투명 PNG 몸 28장, head_base, 표정 3장, 헤어 front/back 각 2종, 장비 4종, 공격 주먹 덮개 6장.
- `manifest.json`, `player.py`, `build.py`, `raster.swift`, `verify.py`.
- `preview_frames.png`: 모든 몸 프레임을 두 헤어와 단검/검, 새싹/별 핀으로 조립한 56개 예시.
- `preview_vs_lineup.png`: 실제 80 px와 3배 240 px를 승인 라인업과 비교.
- `preview_heads.png`: 표정과 두 헤어·장식 조합 확대 검수.
- `preview_animation.gif`: 두 직업의 idle/walk/attack. 공격은 실제 시간으로 재생한다.
- `verification/report.json`: 전체 장착 조합과 좌우 반전의 알파 경계, 손·목 행렬 오차, 접촉 방향, 타이밍 경계, 루프 목 이동량. `asset_bounds.json`은 실측 알파 경계다.

**품질 한계:** 정지 몸은 승인 원화에서 가져왔지만, 전체 캐릭터가 승인 이미지와 픽셀 단위로 동일하지는 않다. 공용 두상 윤곽은 생성 기반이며, 피부 평탄화와 헤어 분리 경계에 차이가 있다. 동작 그림의 옷 주름·갑옷 폭도 프레임 사이에 약간 변한다. 기술 검증 통과가 미술 승인이나 게임 내 비교 완료를 뜻하지 않는다. 요청된 폴더 제한을 지켰으므로 게임 내 컷아웃과의 나란한 비교는 이 패키지를 이식한 다음 단계다.

검증 실행 결과는 **1,344 조합 통과**, 투명 에셋 **46 PNG**, 몸 **28 프레임**이다. 140 ms 접촉 방향은 0°, 손·목 앵커 변환 오차는 부동소수점 허용치 1e-9 px 미만이다. 손 앵커의 실제 몸 PNG 픽셀도 불투명한지 확인한다. idle/walk/cast 목 위치 변화는 80 px 표시 기준 최대 **0.52 px**, 누운 상태를 제외한 몸의 바닥 위치 오차는 원화 기준 최대 **1 px**다. 수치의 자세한 정의와 각 프레임 측정값은 `verification/report.json`에 있다.
