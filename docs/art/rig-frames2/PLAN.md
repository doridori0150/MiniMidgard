# 프레임 스프라이트 v2 제작 및 이식 계약

## 결과와 범위

`minimidgard.frames/2` 파일럿이다. 초보자·검사 각각 여성/남성 선택을 제공한다. 작업과 산출물은 모두 이 폴더 안에 있으며, 게임 코드와 v1은 수정하지 않았다. **실제 게임 적용에는 v2 reference player의 새 레이어 순서를 이식해야 한다.**

- 원래의 28개 몸 포즈를 유지한다. 남녀가 각 클래스의 14개 포즈를 공유하여 논리적으로 56개 프레임 세트가 된다.
- 여성: 01 바보털 단발, 05 높은 묶음. 남성: 02 짧은 뻗침, 03 짧은 옆가르마.
- 머리 바탕 2개, 목 1개, 앞·뒤 머리카락 8개, 이목구비 PNG 52개를 제공한다.
- `preview_frames.png`: 모든 프레임 × 두 클래스 × 두 성별 × 서로 다른 두 이목구비 조합 = 112개.
- `preview_faces.png`: 두 머리 바탕 위에서 각 부위의 모든 타입/표정 변형을 독립적으로 보여 주는 52개 샘플.
- `verification/neck_closeups.png`: 같은 112개 조합의 목을 **원본 픽셀 대비 3배** 확대한다.
- `preview_animation.gif`: 두 클래스·두 성별의 idle/walk/attack을 동시에 재생한다.
- `preview_overview.png`: 네 헤어를 큰 크기와 기준 높이 80px로 비교한다.

검증의 최신 수치·성공 여부는 `verification/report.json`에 기록한다. 검사 구현과 경계 조건은 아래에 명시했다.

## 제작 방식

이미지 생성 도구의 built-in 경로로 승인된 `class_lineup.png`, `hair_faces.png`를 참조한 무표정 머리 원화를 만들었다. 원본은 `source/heads_generated.png`, 요청 전문은 `source/generation_prompt.txt`에 보존했다. 추가 정리 생성 시도는 최종 원화로 채택하지 않았다.

처음에는 색상 분리로 앞머리를 추출했으나, 피부와 머리 그림자의 경계에서 턱 외곽선까지 딸려오는 문제가 있었다. 최종 제작에서는 생성 원화와 승인 스타일을 보고 **편집 가능한 곡선 윤곽**으로 정리했다. 최종 머리·헤어의 원본은 `source/contours.py`, 이목구비 원본은 `build.py`의 작은 도형 정의다. 곡선을 3배 해상도로 래스터화한 후 PNG로 내린다. 승인 원화의 픽셀 복제본은 아니다.

PNG는 투명 배경이다. 피부·크림색 머리·갈색 선·한 단계의 머리 그림자를 사용한다. 눈의 위쪽만 한 단계 어두운 파랑이다. 머리에 그라데이션·광택을 넣지 않았다. v1 몸에 이미 있는 미세한 음영과 복장 변동은 포즈 보존을 위해 유지했다.

## 목이 이어지는 원리

v1은 머리 바탕 끝에 붙인 사각 피부 조각과 잘린 몸 칼라를 맞췄다. 앵커가 일치해도 턱 아래의 실제 알파 픽셀은 이어지지 않았다.

v2는 `assets/head/neck.png`의 완전한 곡선 목 형태를 별도 레이어로 둔다. 목·머리 바탕·이목구비·헤어에 **동일한 머리 행렬**을 적용한다. 단, 목은 몸보다 먼저 그린다. 턱 아래에서 머리 바탕이 목 윗부분을 덮고, 몸의 칼라가 목 아랫부분을 덮는다. 머리가 기울어도 서로 겹치는 면적이 유지된다. 사각형 절단면을 맞대지 않는다.

머리 좌표계는 440×460px, 목 피벗은 `[230, 376]`이다. 목의 곡선은 대략 y=331~422에 걸치며 턱 끝은 y≈367이다. 포즈의 `neck.point`와 `neck.angle`은 v1 값을 보존했다. hurt -8도와 KO -55도를 포함해 제공한 모든 각도를 검사한다.

몸은 포즈·알파·배치·손 위치를 유지한다. 칼라 주변 120×55px 범위에서 기존의 밝은 피부 픽셀을 새 피부색 `[255,229,199]`으로 맞춘다. 검사의 흰색에 가까운 칼라 테두리 광택은 같은 범위 안에서 기본 철색 `[222,221,219]`으로 평탄화한다. 칼라 선과 갑옷 형태는 유지한다. 파일별 변경 픽셀 수는 `source/collar_changes.json`에 있다.

## 성별 처리와 공유 이유

초보자의 짧은 튜닉과 검사의 갑옷은 승인된 SD 비율에서 성별에 따라 다른 체형을 그리지 않아도 자연스럽다. **두 클래스 모두 idle 2, walk 4, attack 3, cast 2, sit 1, hurt 1, dead 1 전체를 공유한다.** 얼굴 변경 때문에 승인된 몸 포즈를 다시 생성하지 않았다.

여성은 둥근 턱, 긴 눈, 얇은 눈썹, 타입에 따라 작은 속눈썹을 사용한다. 남성은 넓고 조금 각진 아래턱, 다른 귀 윤곽, 높이가 낮은 눈, 굵고 곧은 기본 눈썹을 사용하며 속눈썹이 없다. 단순히 머리색으로 성별을 나누지 않는다. 코와 입의 디자인은 공통이지만 이식 시 조회 구조를 단순하게 유지하도록 성별 아래에 동일한 파일 세트를 둔다.

`classes.<class>.bodySets.<gender>`는 공유 이유를 나타내는 참조다. 실제 플레이어는 해당 클래스의 `frames`를 읽는다. 이후 별도 몸을 추가한다면 이 참조를 독립 프레임 테이블로 확장하면 된다.

## 이목구비 선택 계약

캐릭터 생성이 고르는 것은 `gender`, `hair`, `eyes`, `brows`, `nose`, `mouth`의 **타입 ID**다. 몸 프레임이 고르는 것은 `expression`이다. 타입 선택과 표정 변형은 독립적이다. 타입 ID는 두 자리 문자열이며 존재하지 않는 ID나 성별/헤어 조합은 오류다.

| 부위 | 타입 | PNG 변형 | 공통 앵커 | PNG 피벗 |
|---|---|---|---|---|
| eyes | 01, 02, 03 | normal, hurt, closed | [250,282] | [80,30] |
| brows | 01, 02, 03 | normal, hurt | [250,251] | [80,20] |
| nose | 01, 02 | normal | [269,310] | [17,17] |
| mouth | 01, 02, 03 | normal, hurt, ko | [252,333] | [33,23] |

위 앵커는 두 머리 바탕에 공통이다. 부위의 머리 로컬 위치는 `featureAnchor - feature.pivot`이다. 왼쪽/오른쪽 눈은 하나의 이미지에 들어 있다.

| 프레임/명시 표정 | eyes | brows | nose | mouth |
|---|---|---|---|---|
| normal | normal | normal | normal | normal |
| hurt | hurt | hurt | normal | hurt |
| ko | closed | hurt | normal | ko |
| blink | closed | normal | normal | normal |

기본 표정은 몸 프레임에서 가져온다. `expression` 인수를 명시하면 디버그·미리보기·눈 깜박임을 위해 덮어쓴다. 자동 blink 타이머는 추가하지 않았다. 타입별 눈의 폭/높이, 눈썹 형태, 코의 점/짧은 선, 입의 미소/비대칭/중립 형태가 다르다.

## 정확한 레이어 순서

1. 뒤에 있는 무기(`weaponZ == behind`).
2. 머리 행렬로 움직이는 목.
3. 머리 행렬로 움직이는 **완전한 뒤쪽 헤어 실루엣**.
4. 기존 몸 프레임. 목과 뒷머리의 아래쪽을 가린다.
5. 성별 머리 바탕.
6. eyes → brows → nose → mouth.
7. 완전한 앞머리·옆머리 윤곽.
8. 머리 장식.
9. 앞에 있는 무기와 손 덮개.

앞/뒤 헤어는 각자 닫힌 완전한 형태이며 겹친다. v1처럼 한 이미지를 직선 다각형으로 분할하지 않는다. 뒷머리의 두피 부분은 바탕과 앞머리 아래에 숨는다.

헤어 **두 레이어에만** 원래 픽셀 red > 127 조건으로 RGB multiply tint를 적용한다. 알파와 어두운 외곽선은 보존한다. 코·입·몸에는 머리색을 적용하지 않는다.

행렬 배열은 `[a,b,c,d,tx,ty]`이며 x'=a*x+c*y+tx, y'=b*x+d*y+ty다. y축은 아래쪽, 각도는 시계방향 도 단위다. 미러는 부위별 반전이 아니라 완성된 모든 draw의 행렬 앞에 `[-1,0,0,1,800,0]`을 곱한다. 모션은 보간 없는 고정 프레임이다. 공격은 280ms이며 100~180ms가 접촉 프레임, 140ms가 hit 이벤트다.

## 픽셀 검증과 실패 기준

`verify.py`가 `player.assembly()`의 실제 draw 목록을 이용한다. 앵커가 맞는다는 사실만으로 픽셀 검사를 통과시키지 않는다.

- **목 검사:** 28개 몸 프레임 × 성별 2 × 헤어 2 × 좌우 2 × 부위 타입 조합 54 × 표정 4 = **48,384번 실제 합성**한다. 각 합성은 원본 배율 160×160 목 창에 렌더한다. 머리 로컬 x=208..246, y=355..398의 39×44px 내부 통로를 행렬로 옮겨 표본화한다. 완성된 알파에서 마스크를 역산하지 않는다. 알파 <254면 실패한다. 목·피부의 RGB가 245/240/220을 모두 초과하는 흰 픽셀이면 실패한다. 크림색 헤어가 창 안으로 들어오는 경우는 동일한 가림 순서로 렌더한 별도의 재질 마스크로 식별한다. 헤어로 덮인 픽셀도 알파 검사는 그대로 적용한다.
- **절단 검사:** 머리 바탕·목·앞/뒤 헤어의 내부 알파 경계를 검사한다. 알파 경계를 끝까지 추적하고 0.75px 래스터 계단 오차 이내에서 임의 각도의 직선 구간을 찾는다. 수평·수직·양 대각선의 정확한 픽셀 연속 검사도 함께 실행한다. 12px 초과 구간을 `cut_edges.json`에 남긴다. 80% 이상이 어두운 그려진 외곽선이면 자연스러운 윤곽/접선 후보로 분류하고, 선 없이 채색이 잘린 구간은 실패시킨다. 검출된 후보를 숨기지 않는다. 원형 턱의 접선과 뾰족한 머리 끝도 후보가 될 수 있으므로 “긴 경계가 전혀 없음”을 주장하지 않는다.
- **회귀/음성 대조:** v1 플레이어를 읽어서 v2 폴더에만 재현한다. 실제 v1 목 틈과 02 헤어의 잘린 경계를 검사한다. 투명/흰색 픽셀을 넣은 별도 음성 대조 이미지도 반드시 실패해야 한다.
- **앵커:** 모든 제공 프레임·헤어·성별·좌우에서 이목구비 앵커와 무기 손잡이 위치, 캔버스 범위를 확인한다. 28개 몸 파일 모두의 알파가 v1과 동일하고 RGB 변경이 칼라 영역 안에만 있는지도 확인한다. 각 부위 타입 하나만 바꿨을 때 그 부위 파일만 달라지는지 확인한다. 모든 프레임 시간 경계·루프·비루프 마지막 유지도 확인한다.

GIF를 다시 디코드하여 80프레임·40ms 간격·총 3.2초를 확인한다. 네 행 각각에서 idle 2개, walk 4개, attack+recovery 4개의 서로 다른 영상이 실제 존재하는지 해시로 확인한다.

기하학 검사는 모든 미러 조합을 포함한다. `neck_closeups.png`는 정방향 112개의 시각 확인용이고, 미러는 픽셀 검사에서 별도로 합성한다. 색 조합은 선택 개수가 아니라 재질 값이므로 전수 48,384에는 별도의 색상 곱을 넣지 않았다. 컷 검사는 임의 각도를 포함하지만 0.75px 허용 오차와 외곽선 판별이 있으므로 아주 작은 결함은 시각 확인이 필요하다. 새 머리 각도·새 헤어·새 몸을 추가하면 검사를 다시 실행해야 한다.

## 13직업 × 8헤어 × 2성별 확장

몸 프레임과 헤어/표정을 데카르트 곱으로 굽지 않는다. 14포즈 기준 몸은 직업당 14 PNG, 총 182개로 시작할 수 있다. 성별별 다른 몸이 실제로 필요할 때 해당 클래스만 14개를 추가한다. 헤어는 성별당 8개 × 앞뒤 2장 = 32 PNG, 머리 바탕 2개, 목 1개, 이목구비는 52 PNG를 공통으로 재사용한다. 무기·장식은 별도다.

각 직업의 포즈는 머리·손·표정 계약만 제공한다. 얼굴 앵커와 헤어 좌표계를 바꾸지 않으면 모든 직업에서 캐릭터 생성 선택을 그대로 쓴다. 장식은 기존처럼 머리의 공통 skull anchor에 붙인다. 넓은 모자·거대한 머리 장식은 별도 헤어 가림 규칙이 필요하며 이 파일럿에 포함하지 않았다.

## 재현 명령

Python 3 표준 라이브러리와 macOS Swift/CoreGraphics만 필요하다. Python 외부 패키지, 네트워크, API 키는 필요 없다. `--json`은 macOS가 아닌 환경에서도 동작한다.

```sh
cd docs/art/rig-frames2
python3 build.py
python3 player.py --class novice --gender female --hair 01
python3 player.py --class swordsman --gender male --hair 03 --eyes 02 --brows 03 --nose 02 --mouth 02 --state attack --time 140
python3 player.py --gender male --hair 02 --state hurt --facing -1 --json
python3 verify.py
```

`build.py`는 저장된 v1 몸·장비를 읽어 이 폴더에 복사하고, 정리된 곡선에서 머리·헤어·부위를 다시 만든다. v1에는 쓰지 않는다. `verify.py`는 실패 시 0이 아닌 종료 코드를 돌려준다. Swift 바이너리가 없으면 플레이어가 이 폴더 안에서 컴파일한다. 게임 포팅 대상은 PNG·manifest와 `player.py`의 select_frame/matrix/multiply/assembly이며 Swift는 오프라인 시각 검증 도구다.

## 남은 차이

실제 게임 런타임은 수정하거나 검증하지 않았다. 승인된 몸 포즈는 유지했지만 머리 윤곽은 정확한 픽셀 복사본이 아니다. 두 성별의 몸 체형 차이는 의도적으로 제작하지 않았다. 기존 액션 프레임의 작은 복장 변동과 가장자리 잔여 색은 남아 있다. 얼굴의 작은 타입 차이는 80px에서 일부 약해진다. 눈 깜박임은 변형만 제공하며 재생 스케줄은 게임이 선택한다. 13개 전체 직업/성별당 8개 헤어는 확장 계획이며 이번 납품은 두 직업/성별당 두 헤어다.
