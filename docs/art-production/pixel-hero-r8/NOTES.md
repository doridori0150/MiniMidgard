# 참고 이미지의 감성 — 제작 전 기록

브리프가 설명하는 「도깨비의 세계」의 인게임 인상은 작은 몸과 큰 머리, 한눈에 읽히는 눈과 입, 또렷한 어두운 테두리로 요약된다. 머리와 옷은 많은 색으로 부드럽게 섞기보다 몇 단계의 밝고 어두운 면으로 구분된다. 빛과 깊이가 풍부한 배경에 이런 작고 선명한 인물이 놓일 때, 아기자기하면서도 실제로 돌아다니고 싶은 모험 세계의 느낌이 난다. 이는 브리프에 담긴 관찰을 해석한 것이며, 해당 게임 영상을 직접 분석했다는 뜻은 아니다. 타 게임의 캐릭터나 의상, 이미지는 복제하거나 저장하지 않는다.

사용자가 첨부한 6라운드 그림에서는 화면 왼쪽 여검사 쿠키의 크림색 어깨 길이 머리, 파란 튜닉 위 은빛 흉갑, 붉은 허리띠, 흰 바지와 갈색 가죽 장비, 작은 한손검을 계승한다. 큰 그림의 장식과 붓질을 축소하지 않고, 머리 실루엣·눈·흉갑의 빛·붉은 천처럼 작은 화면에서 의미가 남는 요소를 픽셀 덩어리로 새로 설계한다.

P2는 약 2.3등신/46px의 짧고 동그란 모험가, P3는 약 3.4등신/62px로 팔다리와 장비의 구분을 더 읽기 쉬운 모험가를 목표로 한다. 두 비율은 각각 네이티브 격자에서 그린다. 원화 축소, 이미지 보간, 반투명 윤곽선은 사용하지 않는다.

이 참고 설명은 빌드 스크립트와 이미지 제작에 앞서 작성했다.

## 제작 결과와 재현

- P2 `swordsman_female_p2`: 서 있는 몸 46px, 머리 20px, 약 2.30등신.
- P3 `swordsman_female_p3`: 서 있는 몸 62px, 머리 18px, 약 3.44등신.
- 각 비율에 대기 4 / 걷기 8 / 공격 8 / 피격 2 / 쓰러짐 4 / 앉기 1, 총 27프레임. 두 비율 총 54프레임.
- 각 프레임의 몸·검·손가락을 분리한 PNG 162장과, 비율별 단발·포니테일 × 5개 헤어 자세 × 앞뒤 헤어 PNG 40장. 정본 머리 6장은 `source/heads/`에 별도 보관한다.
- `build.py`에 정수 픽셀 도형·선·점과 관절 위치를 직접 정의했다. 제작 스크립트는 참고 PNG나 기존 자산을 읽지 않으며, 큰 이미지의 축소·보간·자동 도트 필터를 사용하지 않는다. 이미지 생성 모델 호출도 없다. `PROMPTS.json`은 실제 제작 지시와 입력 출처를 기록한다.
- 전체 모션과 양쪽 헤어스타일을 합쳐 비율별 26색이다. PNG의 알파는 0 또는 255뿐이다. 피부·흰 바지·금속은 헤어 키와 다른 색을 사용하여 염색 시 변하지 않는다.
- 부츠 바닥 기준은 y=112, 캔버스 원점은 (64,112)다. 발을 들어 올리는 걷기 자세, 몸을 낮추는 앉기·쓰러짐은 의도적인 자세 변화다.

기존에 Pillow가 설치된 Python 3 환경에서 다음 두 명령으로 재생성 및 검증한다. 이번 실행은 환경에 이미 있던 Pillow 12.3.0을 사용했다.

```sh
python docs/art-production/pixel-hero-r8/build.py
python docs/art-production/pixel-hero-r8/validate.py
```

모든 출력은 스크립트가 들어 있는 R8 폴더 안으로 한정된다. 별도 입력 이미지, 외부 통신, 난수 기반 캐릭터 생성은 필요 없다. 잔디 검수 배경만 고정 시드 난수를 사용한다.

## 레이어 계약

`manifest.json`은 `minimidgard.pixel/1`의 프레임 이미지 경로, `head.point`, `head.pose`, 헤어 `pivot`, 검 `z/visible`, 손가락 경로를 유지한다. 몸·검·손가락 캔버스는 모두 128×120, 헤어는 96×96 및 pivot (48,48)이다. `head.point`는 이번 자산의 정본 머리 좌상단 앵커이며, 헤어를 `head.point - pivot`에 붙이면 맞는다.

합성 순서는 **헤어 뒤 → 몸 → 검 → 손가락 → 헤어 앞**이다. 앉기와 쓰러짐에서도 검은 같은 가까운 손에 유지한다. 염색할 때는 헤어뿐 아니라 몸에 포함된 짧은 기본 머리의 네 가지 키도 함께 바꾼다.

`up`, `hurt`, `down` 머리 원본을 매번 그대로 복사하며, 확대·회전 보간은 없다. `down`은 네이티브 머리를 처음 한 번 정수 90도 전치한 정본이다. `up_lift`, `up_forward`는 머리끝만 후행하는 헤어 변형이다. 두 변형도 몸의 얼굴은 `up`과 같고, `head.basePose`로 이를 명시했다. 헤어 스타일 ID는 `bob_p2`, `ponytail_p2`, `bob_p3`, `ponytail_p3`로 분리하여 서로 다른 머리 크기가 섞이지 않게 했다.

각 캐릭터에 독립 `bodyHeight`, `animations`, `hairStyles`가 있다. 최상위 `animations`는 같은 시간표를 공유하고, `canvas.bodyHeight=46`은 단일 높이를 읽는 도구를 위한 기본값이다. 후속 통합에서 비율을 선택할 때는 **선택한 캐릭터의 bodyHeight와 hairStyles**를 사용해야 한다. 현행 게임 렌더러에 캐릭터 선택을 연결하는 작업은 이번 납품에 포함하지 않는다.

## 모션 해석과 시간

- 대기는 250ms ×4. 발은 고정하고 머리·어깨를 1px 올리며 머리끝과 허리 천이 뒤따른다.
- 걷기는 90ms ×8. 가까운 밝은 다리와 먼 어두운 다리가 서로 교대하고, 몸의 높이는 기준/1px 아래/기준/1px 위를 두 번 반복한다. 먼 팔은 몸 오른쪽 바깥에서 크게, 검을 든 가까운 팔은 작게 움직인다.
- 공격은 60/80/140/40/150/90/90/80ms, 총 730ms. 준비 끝과 타격 장을 길게 유지하고, 베기 중간에 팔레트의 불투명한 저채도 선으로 호 하나를 그렸다. 검이 내려간 뒤에는 낮게 거둬들이며 머리 위로 다시 들지 않는다. 마지막 장은 대기 첫 장과 동일하다.
- 모션 규격의 타격 시점 설명에 `약 140~180ms`라는 값도 있지만, 지정된 앞선 장의 시간을 더하면 타격 장 시작은 **320ms**다. 이번에는 명시적인 장별 시간표를 우선했다.
- 피격은 80/160ms. 쓰러짐은 80/100/140ms 뒤 마지막 장 유지. 앉기도 마지막 장 유지다. 마지막 장의 `duration=1`은 기존 계약의 정지 프레임 표기이며, `loop=false`, `holdLast=true`를 함께 기록했다.
- 시전은 별도 이미지를 만들지 않고 대기 4장을 manifest에서 재사용한다.

## 검수 자료와 확인 사항

- `verification/review_p2.png`, `review_p3.png`: 모든 27프레임을 번호와 이름, 시간으로 표시한 4배 nearest 비교표. `verification/rows/`는 모션별 확대 검수표다.
- `verification/play_p2.gif`, `play_p3.gif`: 대기→걷기→공격 20프레임, 그림 3배 nearest, 원래 시간 유지. 한 바퀴 2450ms이며 검수용 GIF 자체만 반복한다.
- `verification/hair_swap.png`: 두 비율 × 두 스타일 × 갈색/검정/분홍 × 대기/공격 준비/쓰러짐의 36가지 조합.
- `verification/game_size.png`: 두 비율을 1배와 2배로 원본 잔디 검수 배경에 배치했다. 실제 게임 실행 화면은 아니다.
- `verification/proportions.png`: 기본 의상과 크림색 단발의 비율 비교.
- `verification/validation.json`: 알파, 합집합 팔레트, 프레임 수·시간, 머리 정본 일치, 손가락/검/몸 겹침, 캔버스 잘림, 고립된 1~3px 잡티, 발 교대, 고정 발, 낮은 검 회수, 대기 복귀, GIF 시간 및 PNG SHA256 검사 결과.

두 비율의 모든 54프레임을 모션별 검수표로 직접 확인했다. 검수 중 발견한 공격 중간의 얼굴 가림, 준비 손이 머리에 파묻히는 위치, 공격 마지막 장의 먼 손 위치 차이, 쓰러진 포니테일의 바닥 침범, 낮아진 자세의 검 끝 위치를 수정했다. 검수표의 아래 여백도 늘려 모든 픽셀이 보이도록 했다. 최종 규격 검사는 994개 항목 통과, 실패 0개다. 육안 판정은 자동 검사만으로 대체하지 않았으며, 얼굴·몸 방향·같은 손·발 교대·검의 일회 베기·헤어 교체를 따로 확인했다.

변경 범위는 이 R8 납품 폴더뿐이다. 기존 아트, `src/`, 게임 설정을 수정하지 않았으며 커밋·푸시도 하지 않았다.
