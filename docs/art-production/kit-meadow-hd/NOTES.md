# 햇살 평원 2.5D 키트 — 제작 노트

## 레퍼런스 해석 (제작 시작 전에 작성)

브리프가 설명하는 ‘도깨비의 세계’ 배경의 핵심은 선으로 둘러싼 평면 도형보다, 위쪽 면과 앞쪽 면이 함께 보이는 입체 덩어리와 재질의 결에 있다. 약 45도 위에서 내려다보는 시점에서 왼쪽 위의 햇살이 잎과 돌의 윗면을 밝히고, 오른쪽 아래로 퍼지는 부드러운 그림자와 바닥에 닿는 어두운 접지 부분이 높이와 무게를 만든다. 손으로 칠한 듯한 표면 변화는 풍부하되, 색과 명암은 캐릭터를 압도하지 않도록 절제한다. 짧고 촘촘한 풀, 흙, 잔돌이 자연스럽게 이어지는 바닥 위에 작은 캐릭터가 또렷하게 읽히는 것이 목표다.

첨부된 현재 나무는 둥근 잎 덩어리와 굵은 갈색 테두리가 특징이며, 현재 필드는 큰 만화풍 소품과 반복되는 풀 무늬가 평면적으로 읽힌다. 이번 제작에서는 판타지 평원의 정체성을 유지하면서 굵은 윤곽선을 없애고, 수관의 부피·나무껍질·돌 표면·접지감을 빛과 질감으로 표현한다. 조선풍 지형이나 건물, 타 게임의 개별 이미지와 배치를 복제하지 않는다.

이 해석은 제공된 브리프와 첨부 이미지에 근거한다. 외부 게임 이미지를 열람하거나 저장하지 않는다. 제작물은 이 디렉터리에만 저장하며 게임 연결은 후속 작업이다.

## 납품 구성

- 바닥: `grass.jpg`, `dirt.jpg`, `path.jpg` — 각각 512×512, 위에서 본 반복 타일. 큰 그림자를 굽지 않았다.
- 소품: `tree`, `pine`, `bush`, `rock`, `flowers`, `stump`, `fence`, `sign`, `well`, `cart`, `haystack`의 투명 PNG 11종.
- 그림자: 위 소품 각각에 대응하는 `_shadow.png` 11종. 모든 RGB 채널은 0이며 알파로만 농도를 표현한다. 투영 그림자 중심은 약 46%, 접지 중심의 최댓값은 49%다.
- 수관: `tree_top.png`, `pine_top.png`. 완성 소품의 같은 좌표에서 잎 부분만 남긴다. 줄기를 제거했으며 남은 픽셀은 원본과 RGBA가 정확히 같다.
- 전경: `foreground_branch.png` — 600×400, 화면 왼쪽 위 모서리용 흐린 잎 가지. 투명도와 색을 함께 흐리게 처리해 검은 가장자리가 생기지 않도록 했다.
- 색보정: `grade.json` — 차가운 그림자색, 따뜻한 빛 색, 채도 0.92, 비네트 0.18.
- 조립 미리보기: `preview_field.png` 390×844, `preview_sheet.png` 1200×1050.
- 제작 자료: `PROMPTS.json`, `source/`, `build_kit.py`, `requirements.txt`, `manifest.json`, `QA_REPORT.json`, `qa/`.

## 크기와 배치 규약

소품의 보이는 높이는 게임 높이의 약 2.3배이며, PNG 위아래에는 각각 2px의 투명 여백이 있다. 원화의 가로세로 비율을 유지했다.

| 소품 | 게임 높이 | 보이는 출력 높이(px) |
|---|---:|---:|
| tree | 100 | 230 |
| pine | 112 | 258 |
| bush | 30 | 69 |
| rock | 25 | 57 |
| flowers | 16 | 37 |
| stump | 24 | 55 |
| fence | 28 | 64 |
| sign | 44 | 101 |
| well | 60 | 138 |
| cart | 40 | 92 |
| haystack | 34 | 78 |

`manifest.json`의 `anchorPx`가 발 기준점이다. 소품은 하단 중앙(아래 2px 여백 바로 위)에 기준점이 있다. 수관은 본체와 캔버스·기준점이 모두 같다. 그림자는 오른쪽 아래로 뻗는 영역이 잘리지 않도록 캔버스를 확장했지만, **기준점의 픽셀 좌표는 본체와 동일하다.** 그림자 이미지를 자체 하단 중앙으로 다시 맞추면 위치가 틀어진다.

배치식은 `drawOrigin = worldFoot - anchorPx × drawScale`이며 기본 `drawScale = 1 / 2.3`이다. 소품, 그림자, 수관에 같은 배치식과 배율을 적용한다. 예를 들어 나무는 세 파일 모두 기준점이 `(124, 232)`다. 본체·수관은 248×234, 그림자는 402×361이다.

권장 합성 순서는 바닥 타일 → 별도 그림자 → 발 y 정렬 소품·캐릭터 → 머리 위 수관 → 전경 가지 → 조명 이후 색보정이다. 나무 본체를 먼저 그리고, 필요한 수관을 캐릭터 위에 같은 위치로 다시 겹친다. 수관을 별도로 잘라서 재중앙 정렬하면 안 된다.

`preview_field.png`는 납품한 타일과 소품을 실제로 조합한 목업이다. 바닥 타일은 0.55배, 영웅 대역은 각각 높이 72px로 그렸다. 단순 픽셀 영웅 3명과 슬라임 1마리는 크기 확인용 대역이며 게임 캐릭터 납품물이 아니다. 모든 소품 11종, 흙길과 석재길, 전경 가지와 색보정을 사용했다. 게임 실행 화면이나 런타임 연결 결과는 아니다.

## 제작 및 재현

원화는 내장 `image_gen`으로 에셋별 생성했다. 채택한 원화 15장을 `source/`에 보존했으며, 전체 프롬프트·재시도·채택 경로는 `PROMPTS.json`에 기록했다. 최초 활엽수는 시점 개선을 위해 교체했고, 잘못 생성된 전경 동물 이미지는 납품에서 제외했다. 외부 이미지 생성 API나 CLI는 사용하지 않았다.

빌드 스크립트는 원화를 다시 생성하지 않는다. 보존된 원화에서 알파를 유지하며 크기를 조절하고, 바닥의 주기 경계를 보정하고, 그림자를 투영하고, 수관 마스크를 적용하고, 미리보기를 조립한다. 수관 마스크는 최종 원화의 잎/줄기 경계를 따라 지정했으므로 원화를 교체할 때 함께 검토해야 한다. 그림자는 실제 3D 광선 추적 결과가 아닌 2.5D 실루엣 투영이다.

Python 3, Pillow, NumPy가 있는 환경에서 저장소 루트 기준:

```sh
python3 -B docs/art-production/kit-meadow-hd/build_kit.py
```

스크립트의 모든 출력은 이 폴더 아래에만 생성된다. 현재 제작에서는 로컬에 이미 설치된 Pillow 12.2.0, NumPy 2.4.4 환경으로 실행·검증했다. 재빌드는 최종 출력과 검수 이미지를 갱신하며 `source/`, `NOTES.md`, `PROMPTS.json`, `grade.json`은 수정하지 않는다.

## 검수 결과

- 세 타일을 각각 2×2 반복해 육안 검수했다. JPEG 디코딩 후 맞은편 경계의 평균 RGB 차이는 grass 1.614, dirt 1.406, path 1.435 / 255다. 주기 경계 보정 전후의 미세한 JPEG 오차는 남지만 눈에 띄는 경계선은 없다.
- 소품 11종의 투명 배경, 그림자 11종의 검정 RGB·알파 범위·오른쪽 아래 무게중심을 검사했다.
- 소품/그림자의 발 기준점 11쌍, 본체/수관의 캔버스와 기준점 2쌍이 일치한다.
- 수관의 유지 픽셀은 본체와 RGBA가 동일하며, 본체 바깥에 알파가 없고 줄기 하단 픽셀이 남지 않았다.
- `qa/tree_canopy_on_gray.png`, `qa/pine_canopy_on_gray.png`는 투명 수관을 회색 바탕에 합성한 확인본이다. `qa/canopy_occlusion.png`는 수관 뒤 캐릭터 가림 예제다.
- 소품의 윗면/앞면과 왼쪽 위 조명 방향은 조립 시트에서 육안 확인했다. 그림으로 표현한 약 45도 시점이며 3D 카메라 수치 검증 대상은 아니다.
- `QA_REPORT.json`에 자동 검증 수치와 원화/최종 이미지 SHA256을 저장했다. `passed: true`로 재검증을 마쳤다.

`src/` 및 게임 설정은 수정하지 않았으며 커밋·푸시하지 않았다. 실제 게임 연결 시에는 새 소품 높이, path 타일, 그림자/수관 패스와 색보정 처리를 연결해야 한다.
