# 어새신 96px 대기 후보 제작 계획

## 사용자 말 (그대로)
- "96px로 그럼 해보자."
- "평타도 마찬가지야. 전반적으로 에셋 작업 시 아마추어보다도 못하게 만드는데 이거 어떻게 해야할까?" (공방 검토 세션 전달)
- "일단 그렇게라도 만든다음 노하우를 이용해서 수정해야지 처음부터 멋대로 대충 만들고 있으니 지금 계속 되풀이하고 있어."
- 그림 규칙 세 가지:
  1. 등신대, 컨셉 스타일, 전반적인 크기 영역을 맞출 것
  2. 레퍼런스를 체크할 것
  3. 스프라이트 애니메이션을 사전에 어떤 동작을 할지 고려하여, 1장씩 생성하고, 연결할 것

## 이번 범위와 순서
- 이번에는 애니메이션 연결 전의 기준 대기 한 장을 후보 A, B로 각각 독립 생성한다. 다른 자세를 만들지 않으며 사용자 선택 전에는 어느 쪽도 SSOT로 확정하지 않는다.
- 동작 계획: 숨을 들이마신 정점의 차분한 전투 대기. 오른쪽 3/4, 양발 지지, 뒷발 고정, 가까운 손의 카타르는 낮게 앞으로 향한다. 이후 대기 애니메이션에서는 이 지지점과 손·머리 기준점을 유지하며 직전 프레임과 비교해야 한다.
- 원본 어새신의 얼굴·마스크·머리·경갑·허리 천 두 갈래·무기 손을 확인했다. 공격 키포즈는 의상과 무기 각도 확인에만 사용한다. 기사는 2등신, 평면 색상과 1~2단 명암, 짙은 갈색 외곽선만 참고한다.
- A 한 장 생성 → 실루엣/얼굴/마스크/무기 확인 → 96px 규격 및 분리 레이어 검사 → A와 기준 이미지의 비교 기록.
- A 검토 후 B 한 장을 같은 요청문과 원래 참고 3장만으로 독립 생성 → A의 검사 결과와 비교하되 A 자체를 입력하거나 수정하지 않음 → 같은 규격 검사.
- 최종: 256×240 RGBA, 실제 키 96px, 머리 폭 ≤60px, 최하단 y=223, 발 기준 (128,224), 머리 키색 4개, 5개 레이어 재합성과 원본 composite 일치 확인.
- 생성 원본은 각 후보 sources/에 보존한다. 후처리는 생성 결과의 픽셀 격자·좌표·팔레트 정규화와 레이어 분리·비교판 조립이다. 48px 원화를 확대하여 새 후보로 사용하지 않는다.
- 참고 원본 파일은 복사하지 않는다. side_by_side.png에는 의뢰서가 지정한 자사 승인 어새신의 비교용 ×2 렌더만 포함한다. 타 게임 참고 자료는 저장하지 않는다.
- 모든 직접 파일 쓰기는 이 폴더 안에서만 수행한다. src/, 기존 작업, Git 인덱스/커밋/원격을 변경하지 않는다.
