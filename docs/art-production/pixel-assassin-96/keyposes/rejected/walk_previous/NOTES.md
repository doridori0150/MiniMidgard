# 어새신 96px 키포즈 10장

대기 1장, 걷기 4장, 공격 5장이다. 중간 프레임과 애니메이션은 만들지 않았다. 공격 재생 순서는 준비 → 정점 → 휘두름 → 접촉 → 회수다. 동작별 시트 첫 칸은 승인된 96px 대기 원화이며 새 키포즈 수에 포함하지 않는다.

## 사용자 말 (그대로)
- 96px 대기 후보를 보고 고름: "B가 훨씬 좋네."
- "96px로 그럼 해보자."
- 48px 키포즈를 보고 한 판정: "예. 휘두르는 걸로 보이지만, 타격감이 좀 떨어져 보여. 동작이 단순해서 그런거 같은데. 그리고 앞쪽 지지발과 뒷쪽 발이 흔들려서 캐릭터 전체가 흔들려 보여."
- "모션은 최소 6~8장은 써야 할 거 같아." — 이 키포즈들을 배치하고, 필요한 사이 장만 더해서 동작마다 6~8칸을 만듭니다.
- 그림 규칙 세 가지:
  1. 등신대, 컨셉 스타일, 전반적인 크기 영역을 맞출 것
  2. 레퍼런스를 체크할 것
  3. 스프라이트 애니메이션을 사전에 어떤 동작을 할지 고려하여, 1장씩 생성하고, 연결할 것

전체 요청 원문은 REQUEST.md에 그대로 보존했다.

걷기의 접지 간격은 223행 발 픽셀 범위 중심 사이 거리로 각각 30px, 30.5px다. 접지는 통과보다 정수리가 3px 낮다. 통과의 떠 있는 발은 `pose.json`의 해당 발 범위가 `null`이다. 원화처럼 대기에서도 가까운 발은 223행에 픽셀이 없으며, 원화의 두 발 모두 그대로 보존했다.

공격 다섯 장의 뒤쪽 부츠는 원화의 216~223행 픽셀로 고정했다. 정점·휘두름·접촉 앞발의 223행 끝점은 181 → 184 → 187이고, 실제 칼끝은 접촉 (219,195)이 가장 앞선다. 휘두름의 잔상 외곽은 실제 칼끝과 별도다. 휘두름과 접촉의 잔상은 `katar`에만 들어간다.

## 제작·대조 기록

PLAN.md를 먼저 작성하고 각 포즈를 한 장씩 생성했다. 매번 승인된 96px 원화를 재첨부했으며 새로 만든 포즈를 다음 생성의 외형 참조로 사용하지 않았다. 각 결과와 이전 장의 머리 크기·상하 높이·발·손의 연결을 육안 대조한 뒤 다음 장을 생성했다. RO 첨부는 걷기와 w-attack1의 순서·리듬만 관찰했으며 파일 저장·복사·픽셀 사용은 하지 않았다.

생성 도구는 내장 `image_gen`이다. 모든 실제 생성 프롬프트와 채택 여부는 PROMPTS.json에 있다. 생성 후 최근접 축소, 실알파 이진화, 승인 팔레트 매핑, 머리 폭 55px 정리, 접지 등록, 보이는 픽셀의 레이어 분리를 적용했다. 대기는 생성 후보를 사용하지 않고 원화 레이어에서 지정 부위를 정수 픽셀 이동했다. 공격의 몸 이동은 뒤쪽 종아리·부츠를 고정한 상태에서 등록했으며, 준비 자세 앞발의 1px 들뜸과 정점의 여분으로 늘어진 천도 정리했다.

레이어 순서는 `hair_back → body → hair_front → katar → grip`. 모두 전체 256×240 캔버스다. 가려진 신체 면을 복원한 교체용 리그가 아니라 현재 포즈에서 보이는 픽셀을 분리한 레이어다. `_4x`는 최근접 4배 확대다. pose.json의 칼끝은 잔상 외곽이 아닌 실제 날의 끝점이며, 그립과 칼끝은 해당 레이어의 불투명 픽셀에 놓여 있다.

## 생성·탈락 수

- 모델 생성: **총 12장**, 그중 **9장 채택, 3장 탈락**.
- 원화 정수 픽셀 편집으로 제작한 대기 1장을 더해 **최종 키포즈 10장**.
- 필수 PNG 산출물: 포즈별 7장 × 10 + 동작 시트 6장 + 공격 비교 1장 = **77개**. 생성 원본·확인용 확대·탈락 후보는 이 수에 포함하지 않는다.
- 탈락 `rejected/idle_pixel_drift.png`: 발과 얼굴·의복 세부까지 다시 그려져, 지정 부위만 이동하고 발을 픽셀 동일하게 유지하라는 조건 불충족.
- 탈락 `rejected/attack_2_high_arm.png`: 카타르 팔이 높고 준비 자세와 너무 비슷하여, 허리 뒤에서 낮게 압축하는 정점 역할 불충족.
- 탈락 `rejected/attack_3_high_arm.png`: 카타르가 어깨 높이로 뻗고 여분의 은색 허리 디테일이 생겨, 허리 높이 접촉·단일 카타르 조건 불충족.

## 파일과 검증

- 각 포즈 폴더: 5개 레이어, composite.png, composite_4x.png, pose.json.
- keyposes_idle / keyposes_walk / keyposes_attack: 각 png 및 _4x.png. 첫 칸은 승인 원화.
- side_by_side_attack.png: 한 행에 승인된 48px×2(왼쪽)와 새 96px(오른쪽), 다섯 행은 공격 재생 순서.
- validation.json: 실측·검사 결과. 재검증: `node docs/art-production/pixel-assassin-96/keyposes/verify.mjs`.
- 검수 과정에서 잔상 일부가 body에 남은 것과 위치 등록으로 잔상에 틈이 생긴 것을 찾아 레이어 경계와 이동 처리를 수정했다.
- 기준 원화 파일은 이 폴더로 복사하지 않았다. 요청된 비교 시트 안에서만 기준 원화를 합성했다. 원본 idle/, src/ 및 지정 폴더 밖 기존 파일은 SHA256으로 보존 확인한다. 커밋·푸시는 하지 않았다.
