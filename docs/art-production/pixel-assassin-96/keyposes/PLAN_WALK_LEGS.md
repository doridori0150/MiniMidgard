# 다리 수정 계획

## 사용자 말 (그대로)
- "앞쪽 지지발과 뒷쪽 발이 흔들려서 캐릭터 전체가 흔들려 보여."
- 그림 규칙 세 가지:
  1. 등신대, 컨셉 스타일, 전반적인 크기 영역을 맞출 것
  2. 레퍼런스를 체크할 것
  3. 스프라이트 애니메이션을 사전에 어떤 동작을 할지 고려하여, 1장씩 생성하고, 연결할 것

## 작업 전 계획
승인 idle는 그림체·등신대·크기 기준, 승인 걷기는 포즈와 보존 영역 기준이다. 참조 이미지는 복사하지 않는다. 새 프레임은 외형 기준으로 쓰지 않고 직전 동작 연결 확인에만 사용한다.

접지 1 → down near(x134) → passing near(x125) → up near(x117) → 접지 5 → down far(x132) → passing far(x125) → up far(x118) → 접지 1 순서. 각 장 생성 후 다리 영역만 반영하고 직전 장 및 다음 접지를 대조한 뒤 다음 장으로 진행한다.

내려앉음은 지지 무릎을 굽히고 뒤 발을 떼며, 통과는 공중 무릎이 지지 다리를 앞질러 간다. 올라섬은 뒤꿈치를 들고 발끝으로 밀며 공중 발을 다음 접지 앞으로 보낸다. y223 접지를 유지하고 정수리 y132/131/128 및 상체·카타르·허리천 원본 픽셀은 보존한다.

내장 image_gen으로 각 다리를 그린다. 생성물 전체를 덮어쓰지 않고 원래 레이어의 다리 영역에만 최근접 축소·팔레트 정규화·접지 좌표 등록하여 합성한다. 보호 영역은 원본 바이트와 픽셀 비교로 검증한다. 접지 중심은 원본 실제 끝점 평균(142.5/108.5, 139/112.5)을 그대로 보고하며 요청의 정수 표기와 구분한다.

기존 여섯 폴더는 rejected/walk_legs_previous/로 이동한다. NOTES, 프롬프트, 좌표 검증, 재생 시트 및 기존 미리보기를 갱신한다. src 및 폴더 외부 SHA256과 접지·대기·공격 파일을 검증한다. 커밋·푸시는 하지 않는다.
